# 工作流与 Agent 交互数据契约

状态：首个纵向切片已实施；版本化表单、外部系统通知和人工补录通道仍在规划中。

## 1. 目标

租户用户不应理解 BPMN 变量表达式、Agent 输入映射或 JSON Schema。平台根据“真实流程路径 + 已发布 Agent 版本 + 冻结的节点映射”生成 UI 无关的数据契约，由不同交互渠道渲染和提交。

该契约同时覆盖：

- Agent 是流程首个环节；
- 用户任务审批后进入 Agent；
- 网关或短时自动节点之后进入 Agent；
- Agent 成功后进入用户任务、另一个 Agent 或流程结束。

## 2. 当前边界

- `agent-engine` 拥有不可变 Agent 版本、输入输出 Schema 和运行账本。
- `workflow-engine` 拥有 BPMN 路径、节点绑定、流程变量映射和流程命令边界。
- 前端只渲染 `ProcessInteractionView`，不解析 BPMN 猜测 Agent，也不直接拼接模型输入。
- 当前不创建空壳 `form-engine`。出现独立表单版本、权限、草稿、数据源和复用需求后，再由表单上下文实现同一稳定契约。

## 3. 命令前交互

### 3.1 发起流程

1. 前端调用 `POST /workflow/process/interaction`，提交定义标识和已有业务变量。
2. 后端按当前变量计算真实首个 Agent frontier。
3. 后端读取已发布 Agent 输入 Schema 和 BPMN 输入映射，返回业务字段。
4. 用户填写字段；前端转换为结构化流程变量。
5. `POST /workflow/process/start` 在事务开始前再次执行同一契约校验，绕过前端的系统调用也不能提交缺失的必填输入。

### 3.2 审批任务

1. 前端调用 `POST /workflow/task/interaction`，后端合并现有流程变量与本次覆盖值。
2. 仅当审批后的真实路径首先到达 Agent 时返回交互字段。
3. 前端提交字段后重新计算参与人要求，避免变量改变网关路径后使用过期预览。
4. `POST /workflow/task/approve` 在完成用户任务前再次执行契约校验。

驳回当前只回到用户任务，不复用“审批后 Agent”契约。未来新增可配置驳回路径时，必须把 action 和目标节点纳入交互请求，而不是在前端推断。

## 4. 运行语义

Agent 节点仍是异步等待状态。流程命令只保存业务变量并进入 Agent 节点；模型调用不在 Flowable 事务内执行。Agent 成功事件应用显式输出映射后，Flowable 自动继续：

- 后继是用户任务：创建任务并执行正常派单；
- 后继是 Agent：创建下一次独立 AgentRun；
- 后继是结束事件：结束流程实例；
- 失败：按节点冻结的失败策略终止、重试或进入未来的人工接管路径。

## 5. 后续扩展

稳定契约可以增加渠道而不改变 Agent/Flowable 领域边界：

1. **版本化表单**：字段布局、字典、权限、校验提示和 Schema 引用由独立表单上下文管理。
2. **外部系统提交**：租户系统通过幂等业务命令提交同样的变量契约。
3. **通知与待补录**：Agent 所需数据尚不存在时，创建受权限控制的交互任务，而不是让 Agent 空输入运行。
4. **复杂结构控件**：对象、数组和文件引用使用 Schema 驱动的嵌套表单/重复项控件；当前通用 JSON 输入只是兼容入口，不是最终租户体验。
5. **契约版本与兼容性**：流程版本冻结 Agent 版本、映射和表单版本；运行实例始终使用启动时冻结的契约。

## 6. 验收底线

- 首节点和审批后节点使用同一后端路径解析逻辑。
- 前端和系统调用都不能绕过必填输入校验。
- 未映射流程变量不会泄漏给 Agent。
- 模型调用失败不会伪装为成功推进流程。
- 新渠道复用应用层契约，不得由 Controller 直连 Provider 或在领域对象中调用外部适配器。
