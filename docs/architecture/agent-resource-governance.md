# Agent 资源治理、跨实例配额与公平调度

状态：目标设计；现有 MCP 调用级治理已实现，统一平台/Provider 治理待实施

更新时间：2026-11-11

执行权威与 G0–G3 以[LangGraph 接入设计](langgraph-runtime-adoption-design.md)为准。本文只定义平台治理，不自研图节点调度、内部 Checkpoint 或第二套恢复游标。当前实现及验收记录以[状态页](../status.md)为准。

## 一、已核对的现状

- Java 原生 Worker 使用固定、有界执行池，默认并发 2、本地队列 20；排队的是领取操作，不是大量已领取租约的 Run。每个执行槽仍可能连续跑完整 Run。
- 当前领取查询先 COUNT(RUNNING) 再锁候选；并发事务可锁不同 Run 且同时看到余量，因此不是严格的跨实例租户硬配额。
- MCP 出站已有 Redis 租户令牌桶、并发硬上限和连接器熔断。它不等于全平台、模型供应商和图执行的公平容量控制。
- 原生 Run 心跳已有共享有界调度池、活动注册硬上限及指标。开源图模块已用同会话 advisory lock + 官方 saver 保护图持久化；商业服务的任务队列/租约不在本方案内。平台继续承担业务命令与资格，不再以原生 nextStep/Recovery 驱动同一图。

## 二、治理分层

| 层次 | 平台负责 | 不能混淆的边界 |
| --- | --- | --- |
| 业务准入 | outstanding 上限、输入/历史体积、deadline、幂等提交 | 入库速率不是运行吞吐，PAUSED/WAITING 也占存储配额 |
| 图启动/恢复资格 | 按租户公平放行、后台管理预留、队列背压 | 只记录线程是否有资格运行，不保存下一节点 |
| 模型/工具调用 | 全局/租户/供应商账户模型/连接器额度、速率、费用 | 两个 Provider ID 共用账户不能各自获完整供应商额度 |
| 图内部执行 | 复用 LangGraph 推进/恢复；外围只保护图实例所有权和执行上限 | Java 不领取内部 Step，OSS 图库不提供平台公平队列 |
| 本机资源 | 有界虚拟线程/异步客户端、CPU 池、连接池、响应体上限 | 本地 Semaphore 不是跨实例硬配额 |

共享资源、逻辑隔离，不为每个租户永久创建线程池或连接池。配额按版本化策略支持平台默认、租户覆盖、Provider 覆盖，并记录生效/审计。专属物理隔离只在明确合规或容量需要时启用。

## 三、平台准入与调用许可权威

目标采用 PostgreSQL 保存平台 outstanding、调用 Permit、预算预留及结算事实；这些**仅是平台治理数据，不含图任务/检查点**。Run 创建与 outstanding 占位同事务，先查业务幂等，终态只释放一次。已有 Run 的恢复不重新申请新业务队列位置，避免满队列使已接收运行无法继续。

调用许可按固定资源键顺序短事务锁定全部所需额度；任何不足整笔回滚，不持有部分额度等待另一额度。Permit 绑定 tenant/run/operation/session generation/claim token，所有续约、释放、结算带条件并检查影响行数，不能无条件 counter--。策略缩容不抢断已发请求，停止新申请并排空。运行服务的领取与平台许可**不是跨库原子事务**：先到治理 Gateway 获准才可真正出站，不能把 backendRun 启动等同已获得 Provider 额度。

现有 MCP Redis 并发机制在统一切换前保持；切换以版本化治理入口为单位，明确哪一侧是硬并发权威，禁止新旧重复扣减。Redis 可继续承担速率和熔断；多 key 原子性须符合部署拓扑，不能假定 Cluster 跨槽 Lua 原子。发送未知时预算/速率消耗保守保留，不因本地失败自动退款。数据库保存调用/用量事实用于对账。

Permit ACTIVE 在确定完成后转 RELEASED；请求可能仍在远端执行则转 QUARANTINED，继续计入上限，待确定取消/完成或有依据的远端最大执行期限后释放。无法核实的写操作转人工，不能凭 TTL 无限重发。fencing 拒绝本地旧提交，不承诺外部 exactly-once。

协调层不可用时停止依赖它的新调用，不把本地缓存提升为无约束备用权威。对账修复异常，不代替正常路径的原子硬上限。

## 四、公平分配与持久等待

按活跃租户的权重、硬上限和等待老化分配启动/调用资格，空闲额度可借用；不抢占已经发出的模型请求。只按 created_at 选 Run 或依赖 runtime 的线程互斥不能证明租户公平。

公平队列状态须跨实例协调，不能每实例各算全局额度。候选扫描有界并记录进度，跳过资源封禁的租户继续其他可用租户，避免头部阻塞。优先级有占比上限；恢复/管理流量有预留且不能饿死普通任务。最低保障以依赖资源可用、未超硬上限为前提，不承诺超售保底。

资格不足时 Gateway 返回稳定 waitRequestId、原因和 nextEligibleAt；图持久挂起，释放执行资源。平台只维护线程/调用资格等待项，runtime 决定其恢复节点。图挂起与平台登记的先后竞态、resume 重复/丢失通过幂等命令、持久状态查询和扫描处理，不靠内存通知。资格短期预留应过期回收，图恢复后重新验证；不能先拿着稀缺 Provider 许可在 runtime 队列里长时间排队。

该集成必须在 G0/G2 验证真正释放运行槽以及有界等待；若所选部署没有安全扩展点，需要调整部署方案，不能在 Java 偷建图任务调度器。拒绝忙循环或为等待每次调用永久保留线程、连接和租约。

手动/API 超额给明确 429/503 和可操作原因；Flowable 节点创建 Run 的准入失败需回滚本次推进事务，走原有有界失败/运维路径，不能先激活等待节点再丢失 AgentRun。已准入的业务等待不重复创建新 Run。

## 五、执行、租约和预算

- 目标 Python Worker 使用受限异步 I/O或有界执行槽；Java 网关可用受控虚拟线程承载网络等待。当前契约模块的 `advance()` 是同步调用，活跃调用占一个检查点数据库连接但非长事务；不能将其测试吞吐当作已完成异步扩展。两侧均保留连接/在途/字节/CPU 上限，异步不等于无限并发。
- 长限流退避、人工等待等持久化后让出；外呼仍在远端运行时不能释放对应远端容量。耗时解析有输入上限或隔离 CPU 池，不假定软超时能强制抢占。
- 三种所有权分开：Java 命令投递租约、runtime 数据库会话独占权、Gateway 调用许可。投递租约过期只允许重投/对账，不允许 Java 接管图内位置；活跃数据库会话不以 TTL 强抢，失联释放时间须测。任何本地所有权丢失都不直接证明远端调用停止。
- 原生旧 Run 的 Heartbeat/Recovery 保留到排空；对新后端不重复注册原生 Run 心跳。平台 session generation 保护平台调用和业务提交，runtime 自身还须保证迟到检查点不能污染恢复。
- deadline 覆盖排队、暂停、退避和重试；跨服务传递绝对截止时间，各进程重新计算剩余并使用单调时钟消耗预算，不能转传本机 monotonic 时间戳。时钟同步、偏差容限与平台最终截止校验纳入部署测试。
- 摘要、路由、Embedding、Rerank、JSON 修复同样计入调用及费用；网关嵌套调用区分业务操作与实际外呼，避免同一父级容量重复扣减或持有全部父许可再等待自身子许可的死锁。

## 六、观测与验收

低基数指标覆盖接收/拒绝、outstanding、可调度等待 P50/P95/P99、runtime 排队与执行、调用 Permit/隔离额度、各类等待/限流/熔断、调用/Token/费用、取消/迟到/重复拒绝、对账积压及状态差异。Run、thread、operation 等高基数关联放 Trace/日志和受权限控制的运维查询，不直接作为无限指标标签。

运维须能区分“业务已接收”“图排队”“额度等待”“人工等待”“外呼中”“结果未知”“后端已完成但业务尚未接纳”；错误不能统一显示运行中或要求盲目重试。

G2 工程容量目标统一见[接入设计](langgraph-runtime-adoption-design.md#8-实施与替换门禁)，不另造冲突数值。强制验收：

1. 双实例抢最后一个平台/租户/共享供应商额度，任意时刻硬上限不超；政策缩容、数据库/Redis 故障及未知请求隔离。
2. 大租户突发、慢 Provider 与独立快 Provider 共存；可运行租户不饥饿，图队列、线程、连接和等待登记均有界。
3. 提交/挂起/resume 每个跨服务窗口丢 ACK、重复消息、强杀与网络分区；不丢任务，不双跑，不把正常 resume 计失败 Attempt。
4. 旧 Worker 复活不能新增外呼、污染图 Checkpoint 或完成业务；仅测 Java 迟到结果拒绝不够。
5. 已成功工具回执与已持久化候选恢复不依赖模型重答；模型响应未保存的未知窗口单列重复成本。
6. P-17 七场景、同租户双采购、连续压缩、JSON 修复、撤权和跨 Run 引用均不退化。

执行顺序：G0 运行服务契约 → G1 治理网关及等价基线 → G2 公平配额/故障容量 → G3 后端权威切换与旧路径退出。当前尚未通过这些门禁，不能因选择 LangGraph 或启用虚拟线程就宣称生产高并发已完成。
