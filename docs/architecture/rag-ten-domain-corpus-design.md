# RAG 十领域知识语料设计

状态：设计稿，尚非已审核的公司制度或已建成的评测集
编制日期：2026-10-17
适用范围：星河科技**虚构**业务测试租户；不得把本设计或后续样例当作法律、税务、劳动或信息安全建议

## 1. 目的和边界

以十个相互关联、但权责边界清晰的业务领域建立可版本化的知识文档。先确定文档体系、业务术语、容易混淆的决策点和冲突处理方式，再逐篇编写正文，最后由独立人员依据冻结版本标注评测样例。目标是检验**证据检索、权限过滤、跨文档判断、时间点判断、引用和正确拒答**，而非制造十个同义词问答库。

现有[员工工作手册](../fixtures/knowledge/employee-handbook.md)是已入库的综合测试夹具，包含 HR、采购、报销、安全与发布摘要。它不自动成为以下十个领域的最终权威文件；新文档不得与之无意冲突。若确需用修订版替代某条规则，必须写明被替代条款、批准者、生效时间及历史适用范围，并重建索引版本。尤其采购 `2,000/20,000` 元区间和报销 `30 个自然日` 为已存在的回归锚点，不得悄悄改数。

所有正文、表格、图、截图及后续多模态资产遵循[RAG 企业知识文档编写与多模态扩展规范](rag-document-authoring-standard.md)。目前表格仅按 Markdown 文本摄取，图片不具备像素解析和资产打包能力；文档中出现图表不代表平台已经支持结构化表格或图像检索。

### 统一文档形态

每个领域首批规划四类资料，而非一篇包罗万象的手册：

1. **政策/规则**：适用对象、定义、判定条件、权限、例外边界与生效时间；回答“应当怎样”。
2. **操作规程**：角色、表单字段、状态流转、证据材料、失败和撤销；回答“如何办理”。
3. **场景与 FAQ**：对照案例、临界值、否定例、常见误用；说明规则如何落地，但不得创设新规则。
4. **版本公告/例外台账**：修订差异、已获批特例、有效期、关联政策条款；不得以未经批准的个案覆盖制度。

每份正文须有稳定 `documentCode`、`version`、`owner`、`reviewer`、`approvedAt`、`effectiveFrom`、`effectiveTo`、`status`、`knowledgeScope`、`sensitivity` 和 `supersedes`，并以文档版本关联知识源/索引版本。`approvedAt` 不等于 `effectiveFrom`；`updatedAt` 也不决定哪条制度适用。正文使用稳定章节号，例如 `PROC-POL-01 §3.2`，以便 Citation 定位。案例中的人名、账户、订单与客户一律使用合成数据，禁止真实密钥和个人信息。

### 权威顺序和答案边界

先按**查询时点、适用主体、组织/合同范围和知识权限**筛出候选，再判断权威：外部法令与监管要求由合规人员维护引用，内部已批准政策高于规程，规程高于 FAQ，FAQ 高于非规范性案例；签署合同只约束其约定主体及事项，不自动修改公司通用制度。同级文件冲突、依据失效或关键事实缺失时，输出 `CONFLICT / INSUFFICIENT_EVIDENCE / NEEDS_HUMAN_REVIEW`，列出冲突引用与缺失字段，不能按检索排名或发布时间自行拍板。权限不足时不泄露文档标题或片段，仅返回授权边界内的证据或拒答。

法律、劳动、税务和隐私事项的测试正文只定义**虚构企业内部流程**；涉及现实法律判断时必须由具名合规负责人核对现行官方来源，并独立记录依据版本。官方文本可用于校验边界，例如[劳动合同法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_0abfdd261c03417b949df19d869add8d.html)区分用人单位与劳务派遣用工，[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)要求明确目的和最小必要范围，[国家税务总局关于数电票入账的答复](https://jiangsu.chinatax.gov.cn/art/2024/4/22/art_16876_3861.html)指向电子会计凭证报销归档规则。测试语料不得把这些外部规则改写成星河科技已实施的制度。

## 3. 跨领域冲突与专门测试轴

| 组合 | 应写出的真实边界问题 | 正确处理路径 |
| --- | --- | --- |
| 采购 × 财务 | 采购获批却无预算或发票不符 | 分别引用采购审批、预算/报销规则；不得互相替代。 |
| 采购 × 法务 | 寻源完成但合同条款未审 | 可说明采购状态；签约结论须按合同权限判断。 |
| HR × 安全 | 员工转岗申请已提交，原权限是否立即回收 | 依据可信 HR 生效状态与安全回收策略；RAG 不直接改权限。 |
| 销售 × 法务 × 交付 | 报价获批、SOW 未签，交付何时开始 | 核对合同和交付启动条件；缺文档则升级。 |
| 客服 × 运维 | 服务已恢复但故障工单和根因单未关闭 | 区分 SLA 恢复点、客户确认和问题复盘。 |
| 行政 × 财务 | 超标差旅已预订，能否报销 | 查预订前批准与财务费用材料，不能由预订事实推定批准。 |

每个领域至少覆盖六种不可混为同类的难例：**精确阈值、版本跨期、角色/对象混淆、状态转换、跨领域证据、缺失或冲突依据**；还要覆盖越权问题、否定问法、同名实体和诱导模型忽略文档的提示注入。跨领域案例只存一份主标注，并标明涉及的所有 scope，避免把同一题复制到不同集合造成指标虚高。

## 4. 编写与评测顺序

1. **先冻结领域契约**：上述代码、负责人、范围、术语表、文档优先级、时间口径、权限矩阵。确认手册的既有锚点是维持还是通过正式修订替换。
2. **按依赖成组写正文**：先采购/财务/HR/安全；再法务/销售/交付；最后客服/运维/行政。每篇正文要给定可计算的条件、反例、缺证情形与升级责任方，不凑篇幅。
3. **双人审查并发布版本**：业务负责人审事实，另一个人审法规边界、跨域冲突和可引用性；只有 `PUBLISHED` 且时间/权限匹配的版本进入默认索引。纯模拟政策需显著标明“虚构测试资料”。
4. **构造挑战样例，而非由原文自动抄题**：题目编写人与答案标注人分开；按冻结的文档版本写 `query`、所需事实、`expectedEvidenceReferences`、允许的答案要点、不可推出的结论、`asOfTime`、scope、主体/租户、风险等级和预期 `ANSWER/ABSTAIN/HUMAN_REVIEW`。待文档稳定后再扩展至每领域数百条，数量不是当前验收指标。
5. **保持盲测与去重**：同一政策的近义句和同一订单的改写归一组，按组切开发/校准/锁定测试集；不得把 FAQ 的答案改写后作为同组盲测题。每次修订生成新 `EvaluationDatasetVersion`，不覆盖旧答案。字段与评分边界见 [RAG 评测用例与数据集契约](rag-evaluation-case-contract.md)。
6. **双层验收**：先测检索（证据命中、误召回、权限、跨期），再测回答（关键结论对应 Citation、错误引用、正确拒答）。对关键路径做 AgentRun→Flowable 回归，但文档问答不能替代确定性审批策略和结构化组织关系。

首轮质量门槛是：每份文件的审批/生效元数据完整；所有临界值和例外有反例；每个标注答案能定位到稳定章节与文档版本；同级冲突有人工复核处置；越权样例零泄露；已索引的员工手册回归不退化。检索/回答的具体数值阈值应在真实基线测出后冻结，不在设计阶段拍脑袋设百分比。
