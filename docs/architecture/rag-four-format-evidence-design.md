# RAG 四格式摄取与证据设计

2026-11-07。目标为 UTF-8 Markdown、Excel（.xlsx）、Word（.docx）与 PDF 的原生证据。第 1–4 节保留目标与设计依据；**第 5 节是已实现范围**。旧纯文本入口保留，.xls、.doc、宏、加密文件不作为可检索格式。

## 1. 对现状的审查

| 已有实现 | 不能直接推广的假设 | 设计处理 |
| --- | --- | --- |
| `KnowledgeManagementController.createDocument` 接收 JSON；`DocumentContent` 对换行等规范化后的 UTF-8 文字计算摘要 | 二进制文件不能经 String 往返；规范化正文也不等于原件 | 独立上传、校验并保存不可变原件；分别记录原件、规范化内容与派生产物摘要，不重算历史身份 |
| `TextChunker` 以字符窗口切分，优先段落/换行边界 | Markdown 能被搜索不等于标题、表头、单位与例外条款不会被切断 | 四种解析器输出结构，再按条款、记录、表格行组切分 |
| `EvidenceLocator` v1 规定除 TEXT_SECTION 外必须有页面区域，包括 TABLE_CELLS | 工作表不是打印页，Word 页码也不是原生稳定锚点 | 新增版本化原生定位，保留已有 v1 分数、引用和回放 |
| Profile 冻结来源索引；已有权限求交、Trace、租约与迟到写入防护 | 新格式不需要另一套检索系统，但二进制预览、解析产物也必须受权 | 复用索引和运行协议，扩展原件、派生、发布和预览边界 |

### 继承旧方案的哪些决策

本设计是范围扩展，不另起一套 RAG 架构。下列机制沿用[既有实施设计 §3–§14](rag-structured-document-implementation-design.md)；“已实现”与“继续采用的设计”分开记录。

| 原有思路 | 四格式如何沿用 | 本轮不做什么 |
| --- | --- | --- |
| 文档版本、解析派生、索引版本各有身份；已发布 Profile 固定来源索引 | Office 解析器升级与 PDF 模型升级同样创建新派生；只有显式发布新快照才改变检索内容。多来源索引冻结已实现，原件/派生全链仍待实现 | 不因换解析器伪造制度新版本，不复制四个知识库 |
| 建议性搜索与驱动流程的检索分开；小块召回与父块/邻域扩展分开（原设计 §8.2–8.4） | DOCX/MD 的局部条款联回有界章节或例外条款；Excel 命中金额行联回所属表头/脚注；PDF 命中续表只联回已验证的同表区域。按同一版本、当前权限、Token 预算组装完整证据组。表级问题如子块从未命中，应单测父级召回表示，而非扩大命中后的窗口 | 不默认整表/整章入模，不用相似度或重复表头决定流程推进；已有组选择契约不等于上下文扩展已实现 |
| 复用已有关键词/向量/RRF、类型化评分与恢复时重验授权 | 四种格式共用同一检索及运行链，只替换可追溯的来源表示；已有评分尺度与版本门禁继续生效。若基线证明需要重排，按完整证据组评，而非按文件扩展名设四套阈值 | 不趁新增适配器更换 Embedding、默认开启 Rerank 或引入第二套 RAG 编排 |
| 固定业务金标、独立来源锚点、分层评测；恢复复用与迟到结果区别对待 | 沿用用例、数据集和采购工具链预期；同题四份原件增加格式维度，先测解析再测召回和最终业务处置。结构定位升版不改旧快照；权限撤销后不能借缓存重读任何格式 | 不重做工具链评分体系，不将人工轨迹或一种格式成功算作四格式真实验收 |

只限 PDF 的部分保留在 PDF 子案：逐页 OCR 覆盖、页面坐标、跨页续表、远端解析任务对账。推广的是它们解决的问题（覆盖证明、精确回源、可靠执行），不是它们采用的坐标或服务协议。

## 2. 一个摄取协议，四种原生适配

上传 → 校验真实格式和授权 → 固定 DocumentVersion 与原件 → 按格式和冻结的 recipe 选择适配器 → 结构与覆盖清单 → 校验 → ChunkSet → 完整来源候选索引 → 原子发布。解析库或服务只产生候选结构，没有发布权限。Markdown/Office 可在隔离的本地 Worker 内执行；MinerU 的 submit/poll/fetch 是 PDF 适配细节，不要求本地解析伪造远程任务。平台统一负责限额、租约、代次、失败原因和审计，LangChain4j 继续服务模型与检索基础设施。

| 格式 | 首版结构与适配方向 | 引用原件的方式 | 必须显式处置的情况 |
| --- | --- | --- | --- |
| Markdown | 按固定方言解析语法树；标题、段落、列表、围栏代码、管道表格；条款继承章节路径，表格行携带表头 | 章节/块和原始行区间；同名标题按块区分 | 不执行 HTML、不抓远程图片；图片替代文本不是图片内容。复杂 HTML 表不当普通表静默解析 |
| Excel | 原生读工作簿、sheet、合并区、单元格类型/显示格式，按有表头的区域识别表。保留原值与显示值；行组继承多级表头、币种、单位和脚注 | 快照内 sheet 标识及名称、范围如 B4:E6；不连续区域分别引用，表头/脚注可作为依赖锚点 | 默认排除隐藏表/行/列并记录排除原因；不执行公式或刷新外链。区分字面量、公式与缓存值，缓存不能证明新鲜；关键结论依赖未核实公式、歧义日期/单位或不明表区时不放行 |
| Word | 原生读正文顺序、标题/编号、段落、原生表及合并单元格，保留条款与脚注关联；图只保留允许的图题和资产引用 | 原件内正文部件、块路径/段落或表格行列选择；页码仅可作派生预览辅助 | 不把批注、删除修订、域代码、隐藏文字作为发布正文；未决修订或关键文本框/嵌入对象无法解释时要求审核，不静默漏读 |
| PDF | 原生/扫描 PDF 由隔离的 MinerU 解析；记录逐页覆盖、阅读顺序、跨页续表及图题；不自研 OCR | 原件摘要、页索引和归一化区域；表格/图片附所选单元格/资产 | 缺页、疑似错合并、关键单位缺失不能标为完整；不承诺任意跨页拼图或从图表像素推断业务数字 |

Office 首轮可用 Apache POI 的 XSSF/XWPF 做小样验证，Markdown 可用可遍历语法树的 JVM 库；这是候选实现，不是已验证所有特征或已锁定依赖。逐适配器记录库/模型版本、方言、读取策略、内存与耗时；Office 不经 PDF 或 Markdown 中转。旧版二进制 Office、宏或密码保护返回明确的不支持原因，不后台自动转换。

## 3. 证据、隔离与失败语义

- 共享逻辑结构：条款、段落、表、行组、脚注和资产引用。每个元素必须映射到本 DocumentVersion 原件；权威性、有效期和租户授权来自来源治理，而非文件扩展名或解析置信度。业务单号的实时预算仍查授权业务工具，不从历史表格推断。
- 拟议 locator v2 以判别类型区分 Markdown 源区间、工作表选区、Word 块/表和 PDF 页区域，不给前三者填虚构页码。比较绑定相同文档版本/摘要及同类坐标；覆盖召回可大于金标，精确引用必须命中目标选择。四份等价材料共享**事实断言**，各自有独立来源锚点，引用另一份不能冒充本份命中。同步升级 JSON Schema、Java Codec、评测、Trace/引用读端与预览，再允许写新版本；旧 v1 按原义读取，不覆写历史 Trace。
- 按业务语义切分：比较运算符、区间上下界、币种/单位、表头与例外作为完整事实组。索引可存小片段，但回答必须取回依赖元素；关联缺失时不给肯定判断。多份材料口径冲突，若无生效版本/权威优先级可裁决，拒答或复核，不按相似度投票。
- 入口验证扩展名、声明类型与实际容器/部件一致；文件大小、解压后字节、条目数、页/单元格数和执行时间设限。禁外部实体、外链抓取、宏和嵌入对象执行；预览不得通过原件下载或隐藏内容绕过权限。只授予片段权限时提供受控片段预览，不直接返回完整工作簿。凭证/业务正文不进入诊断日志。
- 每份产物附覆盖清单：已解析、策略排除、无法解析的位置和原因。非关键可选资产缺失可按已批准策略降级并展示；关键区域未知或无法判断其影响时不得激活候选索引，保留旧版本。任务重试不重复发布；旧 Worker 迟到、删除/撤权、恢复后读取结果沿用平台校验。管理界面区分已收到文件、解析中、待审核/不支持、已索引；绝不把上传成功显示为可检索。

## 4. 同题异源验收与交付顺序

1. **先做可运行的基线。**用已有采购 Markdown 和 P-17 只读预算夹具，按[工具链路评测](rag-evaluation-and-routing-delivery-plan.md)分别评证据、调用参数、判断和流程状态；不等待二进制适配器。另制作同一审批规则的四份真实文件，人工审核各自的原件锚点、单位与上下界。一个发布基准不混放四份重复材料：先按格式隔离索引/权限，避免检索用易读副本掩盖另一适配器失败。
2. **公共底座 + Markdown 结构化。**冻结原件/派生身份、覆盖清单、locator v2 读写、授权预览和发布协议；先跑通 Markdown 的结构切分与旧引用回放。复用[实施设计](rag-structured-document-implementation-design.md)的租约、完整索引 Manifest 与恢复门禁，不复制四套表/Worker。
3. **Excel、Word 各交付一个纵向切片。**采购试点先 XLSX 金额矩阵，再 DOCX 条款与例外。每个切片必须从真实上传、索引、检索到点击 Citation 定位原件，并通过格式负例与权限测试。PDF 的 D0（真实版本、许可、产物、质量/资源试跑）可并行；只有 PDF 切片依赖 MinerU D0。四条路径各有支持矩阵，未过门禁者不开放为已支持。
4. **联合验收。**问 2,000.00、2,000.01、20,000.00、20,000.01 元分别需要哪些审批；将数值不变而表头单位改为“万元”作反例。检验“必要时采购委员会审批”不被解释成一律需要。再混合来源测试冲突、撤权及证据不足；不从问答成功推断流程已推进。

| 分层验收 | 报告必须能回答的问题 |
| --- | --- |
| 解析 | 每格式的关键事实、单位、表头、例外是否完整？能否排除 Excel 隐藏行、Word 未决修订、PDF 假续表、Markdown 围栏中伪表等负例？ |
| 检索与引用 | 固定模型、Profile、问题和权限，分别记录每格式事实组覆盖、精确定位命中、未判定数和失败原因；不能只报四格式平均分 |
| 运行与治理 | 引用能否以当前权限打开？关键事实缺失时是否拒答/复核且不错误推进？重试、强杀与晚到是否污染旧 Profile 或重复激活？ |

审核夹具上，越权、金额边界/单位误判、伪造定位、关键缺失仍放行、迟到覆盖都应硬阻断。比例与性能阈值须按格式实测；不从一个采购场景推导发布级成绩。

## 5. 已实现的原件切片

- `POST /knowledge/originals` 接收 multipart 的 sourceCode、externalDocumentId、version、file。管理权限与旧文档接口一致。保存原始字节和 SHA-256（单件 2 MiB），与解析 recipe、覆盖清单、派生内容和既有索引区分。相同租户/来源/文档版本重交相同原件幂等；换字节或试图覆盖旧文本版本均拒绝。V60 不重算历史版本/Trace。
- `GET /knowledge/originals/coverage` 按同一文档身份返回已解析位置和排除原因。PARSED 表示已解析并排队，不等于 ACTIVE；不支持的 DOCX/PDF 保存原件和 NOT_INDEXED 清单，不排队、不替代旧活跃索引。拒收伪装/超限包。当前解析同步有界，索引仍走原租约 Worker；未实现对同一原件在线重解析和切换 recipe。
- CommonMark/GFM 解析 Markdown 段落及表格行；代码块不作为政策，HTML/图片等未经解释的内容不发布。POI/XSSF 解析可见工作表的行、数值原值和显示值、横向合并位置。隐藏行列/表剔除并记录，公式、错误单元格、纵向合并、图形/嵌入对象等不予索引。不把通用表语义或任意公式新鲜性当作已解决。
- `GET /knowledge/citations/preview?traceId=…&chunkId=…` 使用已认证主体和可信租户。在同一 SQL 中核对成功 Trace 的原引用、已发布 Profile 与冻结索引、当前主体范围、来源与文档状态。仅返回匹配块、原件 SHA、recipe 与 v2 原生位置；猜测块、撤权和跨租户返回 404。Markdown 为原始行区间，Excel 为原工作表选区；Word 块和 PDF 区域有位置契约，但没有解析器生成可用引用。此协议未替换历史 EvidenceLocator v1 评分。
- 需要驱动流程时可在 PLATFORM_AGENT 的发布输出 Schema 声明 `x-workflow-citation-claim` v1：`amountField` 对应数值输入，`above` 为不含下界，`decisionField/disposition` 为该档审核通过的处置，`citationsField` 为输出引用数组，`requiredChunks` 为审核人固定的块 ID。要求已绑定 knowledge_search。模型不能自定必要证据。校验仅接受本 Run 已观察且仍授权的工具引用，缺少任何一个、金额不适用或给出其他处置均拒绝；此门禁只保证已声明的结构化决策，不是自由文本通用 Grounding。没有在生产发布采购测试草案。
- [采购报告及复跑入口](../fixtures/knowledge/pilots/procurement-approval-v1/README.md)。两条原生路径分开建索引，使用同一 B04 原题；DOCX/PDF 仅核对原件和未索引状态。

### 交叉评审后的约束

- 发布事务锁定 Agent 草稿；必要块必须全部属于该租户已发布 Profile 的冻结来源/索引，且来源、文档当时可见。发布不授予任何人的读取权限；执行、历史回放和引用回读仍用当前授权。
- 工具结果的正文只在 `evidence` 出现，`citations` 只保留身份与定位。整组序列化后超过 Registry 的 20,000 字符预算即返回 `KNOWLEDGE_EVIDENCE_BUDGET_EXCEEDED / PARTIAL`，不截掉限定词，不把 SUCCESS Trace 当作已向 Agent 交付的证据。
- 原件与 ZIP 展开限制之外，解析器还限制派生 UTF-8 正文与排除说明合计 2 MiB、每块 8,000 字符、最多 4,096 个排除位置；在遍历过程中检查 10 秒预算。同步第三方解析调用不是可强制抢占的沙箱。
- 知识库管理页支持二进制原件上传；“回读引用”用检索 traceId 和 reference.locator 获取当前允许查看的片段。它不是原件下载或 Office/PDF 图形预览。
