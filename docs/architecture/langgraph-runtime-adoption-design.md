## 1. 决策与官方能力对照

采用 LangGraph 承担 Agent 内部循环、分支、并行、状态、Checkpoint 和中断恢复；Java 保留业务 Run、权限、配额、工具回执、证据验收与 Flowable 完成权。**撤回自研通用 ExecutionTask/Continuation 调度器方向，不同时维护两套内部游标。** 这不是“LangGraph 自动满足高并发”，也不是今天已经迁移。

2026-11-11 核对官方资料，区分已有框架能力与本项目接入要求：

| 资料 | 已有能力/限制 | 项目决策 |
| --- | --- | --- |
| [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)、[Checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers) | 图状态、super-step 检查点、pending writes；历史 replay 会重新执行后续节点 | 复用内部恢复，不再自研图任务依赖；replay 不是业务安全重试 |
| [Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts) | resume 从中断节点开头重新执行；中断前副作用须幂等 | 外呼前持久化稳定意图，工具回执仍由平台管理 |
| [Agent Server](https://docs.langchain.com/langsmith/agent-server) | 是图库之外的服务交付层；生产自托管有商业许可要求 | 不采用商业服务；不能把其队列/Worker 能力记为 OSS 图库已有能力 |
| [LangChain4j Agents](https://docs.langchain4j.dev/tutorials/agents/) | Agentic 仍标实验性，默认异步待执行任务随 JVM 退出丢失 | 不与 LangGraph 编排同一链；继续复用 Java 模型、Embedding、MCP 适配 |

选型原因是内部编排持续演进与现有执行器重叠，不是工具数量或框架流行度。容量治理、授权、副作用和业务完成均不因选型自动解决。

## 2. 三层职责与唯一权威

```text
Flowable：业务网关、人工审批、流程生命周期
    ↕ Java 应用服务及完成 Outbox/Inbox
Java 平台：Run / AgentVersion / 权限 / 配额 / 结果验收
    ↕ 持久提交、查询、取消、恢复命令及结果核对
开源 Python 运行模块：LangGraph 内部图状态、Checkpoint、中断
    ↕ 受信执行身份 + 稳定 operationId
Java Model / Tool / Knowledge Gateway：适配、授权、回执、证据
```

| 事实 | 唯一权威 | 另一侧保存什么 |
| --- | --- | --- |
| Run 业务状态、deadline、主体、最终结果 | Java | 图保存关联 ID，不直接完成 Flowable |
| 图当前位置、节点依赖、合并状态、重试位置 | LangGraph | Java 保存 backend/thread/run/checkpoint 引用与审计，不推算 nextStep |
| 工具请求身份、参数哈希、执行状态、可信回执 | Java 工具账本 | 图持引用与允许使用的内容 |
| 模型预算、已持久化原响应、费用事实 | Java Model Gateway | 图按响应引用推进；Gateway 不决定下一图节点 |
| 知识快照、授权、原文、Citation、Grounding | Java | 图消费受限证据，不能指定任意租户或绕过授权读库 |
| BPMN 人工任务与流程去向 | Flowable / Java | 图只接收验证过的人工输入或完成结果 |

Java Step 在目标后端中是统一执行时间线的展示概念，不要求再写一份 agent_run_step；优先从调用与治理账本查询组装，仅在有明确查询性能需求时增加可重建的物化投影。时间线和投影均不得用于恢复新图的执行位置。当前尚未切换，原生 Checkpoint v5 继续服务现有路径；切换后只服务旧运行排空。新后端不额外维护可驱动执行的 v5 快照。图状态只能通过运行模块接口变更，Java 不直写其检查点表。

### 2.1 职责重叠审查与调整（2026-11-16，待实现）

2026-11-20：已实现显式启用的第一阶段 v2 契约，详见[实现范围与剩余边界](../quality/graph-v2-intent-regression.md)。本节其余调整仍按待实现计划推进。

以当前图链路为基线，未发现 Java Gateway 再包一层完整 Agent 循环，但回执校验隐含了固定线性协议。以下属于扩展约束，不表示当前顺序图必然执行错误；也不应以删除安全校验来“去重”。

| 重叠位置 | 当前约束与风险 | 调整方向 |
| --- | --- | --- |
| JdbcGraphCognitionStore.historyLocked | 连续 model:N、每次非最终响应一个工具、严格引用顺序、候选后不再 MODEL、固定 validate:1；Java 隐含重建 MODEL→TOOL→MODEL→VALIDATE 路径 | 图负责内部顺序与恢复；Java 按本次请求的可信引用、因果绑定及业务前置条件校验，不靠全局连续序号推导 nextStep |
| finishModel 与图 prepare_tool | Java 用历史工具数 +1 绑定参数位置，Python 用 tool_calls +1 生成操作 ID；多工具、并行和修复后容易分歧 | 接受模型决策时分配并持久化稳定工具意图 ID，图原样引用，双方不再独立推导序号 |
| GraphCognitionGateway.model | Java 拼接完整历史工具结果；若图引入摘要/按需回读，Java 仍全量拼接就会抵消图的上下文策略 | 图声明有序的上下文引用及用途，Java 授权解析、执行大小限制并注入平台强制规则，不自行决定下一轮记忆策略 |

**交给 LangGraph：** 节点和条件边、分支/并行合并、内部逻辑重试位置、Checkpoint 游标、interrupt/resume、Plan/摘要/修复节点的位置与执行顺序、上下文选择策略。框架能力仍需我们定义节点，不代表它能自动做业务判断。

**必须保留 Java：** Run/业务 Attempt、版本绑定、当前执行资格、可信参数与原响应、工具幂等和不可变回执、权限/数据范围、总预算/费用/纠偏限制、事实与业务规则、持久停止裁决、最终业务接纳及 Flowable Outbox/Inbox。图内预算是早期限制，Java 是跨实例硬边界；图内 VALIDATE 与最终提交前复核的时点不同，应复用同一校验策略，不维护两份互相漂移的规则。数据库会话锁保护图写入，与 Java generation 保护调用/提交互补，不作为重复机制删除。

#### 契约演进，不把安全责任一并移走

1. **稳定操作身份。** MODEL 的逻辑意图在图中先持久化；Java 原子保存模型原响应、规范化决策和该决策产生的工具意图列表，每项绑定 tenant/Run/模型操作/工具/参数摘要。丢 ACK 重放返回原列表和原 ID。工具意图 ID 作为后续 TOOL operationId，物理重试另有 callAttemptId；缓存恢复不换 ID，新的合法重复调用须由新的已接受决策产生并受防循环检测。图计数用于限额提示，不再作为唯一身份来源。
2. **不信任任意引用集合。** Java 核验每个引用属于当前 Run、主体和冻结版本，来源已提交、未撤权、未被明确失效，并检查声明的依赖和必需业务事实。删除严格历史顺序不等于允许漏传关键否定证据：最终验收从可信事实账本核验任务契约和相关矛盾，不只看模型挑选的证据。摘要引用保留来源关系，不能取代原件或升级为业务事实。
3. **候选不是终态。** 图可在预算允许且未持久停止时生成新的修复候选；校验请求绑定具体 candidateRef/digest、校验策略版本及事实版本，幂等 ID 不再固定 validate:1。Java 原子接纳与 Run/执行代次及最终选定候选绑定，不能复用旧候选的通过回执批准新候选；已经提交的业务终态禁止被图修复覆盖。
4. **记忆策略与安全解析分开。** 图选择工作记忆/证据引用，Java 保留 system 级强制规则、可信输入、授权、引用与大小校验。图不能选择任意凭据、租户、URL，也不能靠删掉待解决事实让无进展计数归零。平台可因缺必要输入拒绝一次调用，但不因此自行跳到另一个图节点。
5. **版本化迁移。** 升级 wire/图状态/模型及工具意图契约，冻结 artifact 与对应适配器；旧 ordinal 和 validate:1 继续由旧版本入口处理，不修改旧回执或用新规则恢复旧图。先并行验证新契约，只对新发布版本启用；旧运行排空后删除线性 history 重建逻辑和原生内部恢复实现。平台审计 Step 只做投影，不能重新成为 nextStep 权威。

#### 验收及复核结论

- 单次模型返回两个工具、交换合法执行顺序、并行回执乱序到达，均可继续；无必要前置事实时仍拒绝。
- 候选校验拒绝后图有限修复可再校验，但不能重用旧通过回执、重置 Run 预算或解除停止裁决。
- 模型决策落库后 ACK 丢失、分片恢复/新代次接管，工具意图 ID 保持不变，实际成功外呼不因序号重算重复执行。
- 图省略关键否定事实、使用其他订单引用、撤权摘要或旧事实版本，平台最终验收仍阻断；不因“图说依赖满足”放行。
- 上下文摘要后不再由 Java 自动拼回全部旧原文；缺证仍有明确回读/拒绝路径，权限与输入上限不降低。
- 旧版本图、原生运行、P-17 七场景和最终 Flowable 去向均回归；证明增加合法图分支不再要求修改 Java 线性路径假设。

结论：当前主要是协议层的线性耦合，不是两套 nextStep 已同时运行。先解除连续序号、单工具历史与唯一校验 ID 的假设，再迁移 Plan/摘要/并行；不能先开放新图能力再补安全契约。阶段验收应记录删掉了哪些内部恢复/顺序代码、保留了哪些治理门禁，而非只统计新增框架代码。上述调整与 §5.1 防循环、§5.2 Plan、§7.1 安全接管共同生效。

### 2.2 执行时间线优先复用账本（2026-11-24，待实现）

不因界面需要展示 Step 就重复持久化一套模型/工具状态。LangGraph Checkpoint 回答“从哪里恢复”；Java 调用账本回答“什么操作已提交、有什么结果”；时间线回答“本次任务经历了什么”。时间线既不是图游标，也不是独立的成功事实来源。本节修订 §2.1 中“Step 只做投影”的表述：首先采用查询时逻辑投影，不强制物化落表。

**首选数据源。** 模型调用复用 agent_graph_model_call，工具复用 agent_tool_execution_audit；引用关联 agent_graph_reference，物理发送/返回事实复用 V75 的 agent_graph_call_dispatch / agent_graph_call_outcome，并通过许可/预算账本关联逻辑操作和 callAttemptId。校验、Plan、停止等展示读取各自已持久的治理回执，不从模型自述或日志字符串推断成功。物理 RETURNED 只证明请求返回，不等于业务操作成功；缺回执明确显示未知或记录不全，不能靠 Checkpoint 或投影补造成功。

**统一查询契约。** 在应用查询层输出统一 TimelineEntry：来源类型及来源记录 ID、tenant/Run、可用的业务 Attempt、operationId、物理 callAttemptId、动作类型、状态、时间、原因码和回执引用。entryId 按来源类型与真实稳定键派生，不要求先有 agent_run_step 主键。逻辑动作聚合展示，物理重试保留可展开记录，不按工具名合并不同操作。不是每个 prepare 节点都要生成业务动作条目；Checkpoint 也不能当成完整审计日志。

查询必须按租户和 Run 访问权限过滤，再对结果引用做当前数据授权；不得直接向浏览器暴露 system-worker 治理表。来源没有 Attempt/时间等字段时返回明确缺省，不绑定“当前 Attempt”伪造历史。跨来源时间排序使用稳定来源键打破同时间排序歧义，不能把墙钟顺序当作因果顺序；分页采用有界的稳定游标，并明确可见水位/最终一致性，不无界加载全部账本。诊断结论的证据引用需关联实际回执，查过数据不等于结论采用了它。

**审计发生时间。** 审计指事实的追溯用途，不是运行后另找时间保存。执行前登记调用身份/发送事实，结果返回后在短事务中保存结果/回执，提交后才向图返回成功。既有外呼未知窗口仍按幂等和对账处理；不跨远端调用持有长事务。时间线读取这些事实无需额外写 Step。

**可选物化条件。** 只有实测跨账本查询无法满足分页、统计或保留期要求，才增加轻量投影，记录状态摘要及来源引用，不复制完整参数、输出或另一套状态机。可以与权威账本同事务更新，也可以通过可靠事件或可重扫的变更游标幂等补齐；普通内存事件不保证不丢。投影延迟/失败只影响查询新鲜度，不重新调用工具、不阻止已提交事实恢复；权威事实写入失败仍必须阻断成功。投影不能修改账本、解除停止或触发业务完成。保留期和来源清理须一起设计，不能让未过审计保留期的引用悬空。

**兼容与验收。** 原生路径现有 agent_run_step 写入与进度事务保持，未核验前不删除表或改它的恢复职责。现有 stepId API/评测契约需版本化适配为稳定动作关联，不能静默把 UUID/operationId 塞进旧数字 ID。验收至少覆盖：无 Step 行仍可呈现新图调用时间线；同操作多个物理尝试不丢失；跨租户和撤权结果不可见；回执已提交但图未更新不误重调；可选投影缺失能重建；分页无重复/遗漏的约定得到测试；原生详情与评测仍兼容。

方案审查结论：与 Run/Attempt、回执幂等、Checkpoint 唯一权威、预算及安全接管无冲突；需要修订的是强制 Step 落表及固定 stepId 关联要求，而非删除可靠调用账本。新增时间线查询和旧接口适配仍待实现，本次不改数据表、接口或运行逻辑。

## 3. 部署与组件复用

用户于 2026-11-11 明确选择开源路线：采用 **Python LangGraph 开源库 + 官方 PostgreSQL checkpointer**，不购买/依赖 Agent Server 或 LangSmith 服务。`agent-runtime-langgraph` 锁定 `langgraph==1.2.20`、`langgraph-checkpoint-postgres==3.2.0`、`psycopg==3.3.8`，完整传递依赖由 `uv.lock` 固定。软件许可与部署资源费用是不同问题，不承诺数据库、模型或基础设施免费。

不复制商业 Agent Server。平台仅提供已需承担的持久业务命令、准入与公平资格；Python 有界 Worker 领取图实例执行资格，使用框架原生状态推进。不得另建通用节点任务依赖、nextStep、内部重试游标或图画布。当前模块有同步 `advance()`、官方 saver、HTTP 适配和 Java 工具桥接，生产身份/派发及 MODEL/VALIDATE 尚未接通；图库不等于分布式服务，完整 G0/G2 仍须实测。

PostgreSQL saver 与会话级 advisory lock 使用**同一个不自动重连的连接**；图运行结束/持久挂起后关闭连接释放所有权。不以 TTL 过期强抢存活会话，数据库连接丢失后旧 saver 不得自行重连写入。Java 的 session generation 另外阻止旧外呼/提交。每个活跃图调用占一个连接但不持长数据库事务；Worker、连接和在途须统一有界，故障接管时延还受 TCP/数据库失联检测影响，不能当成已实现低延迟接管。

图库的 LangSmith SDK 传递依赖不代表购买服务。模块显式关闭自动云追踪，未来可观测出口由平台统一配置。数据库 setup 只在部署迁移阶段执行，运行账号不使用 DDL 权限；官方 saver schema 与 Java Flyway 分开管理。

Java 保留 LangChain4j Provider、Embedding、MCP Client；图经受治理端口访问，Python 不保存 Provider/MCP 密钥、不直连业务库。不再引入 LangChain4j Agentic 或自动执行工具的高层代理。框架决定下一动作，平台决定动作是否获准。

## 4. 身份、版本与跨服务命令

- AgentVersion 冻结 executionBackend、graphArtifactDigest、graphStateSchemaVersion、运行服务/持久化兼容版本，以及工具快照、知识 Profile、预算和验证策略。部署路由须保留旧 artifact，不能以同名图最新代码恢复旧状态。
- platformRunId 是业务目标；threadId 是隔离的图状态空间；backendRunId 是一次平台登记的 runtime 调用（不是商业服务 ID）；operationId 是逻辑调用；commandId/eventId 用于去重。身份不互相替代，不接受模型自报租户/主体。
- 一个业务 Run 固定一个后端与状态线程。普通暂停/resume 可产生新 backendRunId，但不增加业务失败 Attempt。业务 Attempt 只计经批准的失败尝试，图节点调用重试另记，指标不得混用。
- 新 `AgentExecutionBackendPort` 提供异步 submit/query/resume/cancel，提交返回关联引用，不占 Java Worker 等完整 Run；DTO 不暴露框架类型。请求携带协议版本、commandId、Run/主体、artifact、输入引用/摘要、绝对 deadline 和预算版本。
- resume 指明 waitRequestId、最新 checkpointId 与当前 session generation，不能只凭 threadId 恢复任意历史状态。平台命令登记负责薄适配去重，不新增内部节点状态机。G0 必须证明 ACK 丢失后仍能找回同一次提交，不能重建随机线程。

Java 同一事务完成准入、Run 和待发送命令记录，提交后唤醒、扫描兜底；不持数据库事务调用远程服务。ACK 丢失按稳定关联查询对账，未证明未接收前不重复启动独立执行。内部结果和下一节点由框架持久化机制接管，**不要求图 Checkpoint 与 Java Run 跨库原子提交**，不为每个图节点复制 Java Outbox。

图完成只产生结构化候选和证据/回执引用。Java 核验租户、Run、版本、权限、已登记操作、Schema、拒绝信号与 Grounding，再在平台事务写最终结果和 Flowable 完成 Outbox。消费方继续 Inbox 去重并验证活动节点，图成功不等于审批通过。

回调丢失由 Java 查询后端持久输出补偿；事件至少一次，按后端运行/序号去重，SSE 仅展示。Java 校验通过但终态事务失败，重验同一候选与当前权限，不要求模型重答。

业务审批仍由 Flowable 管理。图需要人工输入时提供稳定 waitRequestId，平台幂等关联人工任务；验证任务状态、修订号、权限后 resume。图挂起与 Java 登记不是同事务，须通过可查询的持久等待事实、幂等登记与对账覆盖先后竞态。

## 5. 回放、幂等、重试与摘要

1. 独立“确定意图”节点持久化 operationId、调用标识、参数摘要与预算引用，可靠提交后才能进入外呼节点。验证所选部署的同步持久化边界，不能依赖异步 checkpoint 恰好先落库。
2. 工具键保持 `platformRunId + logicalOperationId + toolCode`；参数哈希单独比较。恢复、Worker、backendRun、Attempt 改变不换键；FAILED/过期重新领取仍查哈希。
3. 工具成功但图 checkpoint 未写，恢复已提交意图并授权回用原回执，不重新选择工具。模型原响应已持久化也按稳定意图回用，解析/验证不依赖再生成。
4. 远端成功但本地未保存回执仍存在未知窗口。Checkpoint 不保证外部 exactly-once；有外部幂等/查询能力才可对账，未知写操作人工核验。模型响应丢失可按显式预算重复生成并记录成本，不能承诺零重复费用。
5. 图负责节点重试位置/节奏，Java 强制次数、Token、费用、deadline 总上限。SDK 隐式重试关闭或纳入同一预算，不叠加“平台三次 × 图三次 × SDK 三次”。普通等待、resume 和安全接管不算业务失败重试。
6. 历史 replay/fork 不是默认运维重试；获准的业务重新执行另建 Run 并关联来源。不能把参数变化、换制度快照混入同一逻辑操作。

摘要和 JSON 修复也经过 Model Gateway、证据绑定与预算。增量摘要、按需原文回读、防串单仍是平台业务约束，迁移为图节点不能退化为默认消息裁剪，不能让摘要取代关键原文。

### 5.1 无进展检测与防循环（设计 2026-11-16，部分实现 2026-11-20）

2026-11-20 进展：已实现 v2 确定性动作/结果重复和短周期检测，并接入 V71 持久停止及无模型收尾；见[实现与验收边界](../quality/graph-v2-loop-regression.md)。已增加必要事实清单、确定性事实校验及循环触发的一次纠偏，见[V73 验收](../quality/graph-v2-checklist-correction-regression.md)；连续业务无进展判定与轮询例外仍待实现。

目标：阻止模型在 A→B→A→B、重复检索、反复修复/重新规划中耗尽资源；既不把正常取证和轮询误判为循环，也不允许分片恢复或重试刷新额度。本节是新增设计，不表示现有 maxSteps、SliceBudget 或调用回执已经完成语义循环检测。

**职责和权威。** LangGraph 保留内部执行游标与检测上下文；Java Gateway 保留 Run 级预算、幂等判定记录和不可逆的停止裁决。新增治理数据不含 nextStep，不构造第二套图调度器。图提出动作时携带检测策略版本、当前事实版本和相关回执引用；网关基于受信回执校验，不接受模型自述“已有进展”。判定必须覆盖 MODEL、TOOL、路由、摘要、修复等所有入口；最终 Flowable 接纳也检查停止裁决。

#### 预算口径与恢复不变量

| 额度 | 权威、计数和重置规则 |
| --- | --- |
| SliceBudget | 仅本次执行片段的次数/时间；新片段可重置，只决定让出，不授予新的 Run 预算 |
| Run 逻辑动作上限 | 按 tenant + Run + operationId 幂等登记；操作摘要不一致拒绝。同操作回执恢复不重复扣逻辑次数，新 operationId 必须扣次 |
| Run 物理外呼/Token/费用 | 每次实际发送（含重试、路由、修复、摘要与嵌套调用）按独立 callAttemptId 预留；所有业务 Attempt、generation、backendRun 共用累计账本 |
| 纠偏额度 | 全 Run 最多一次模型纠偏（试点默认）；重试纠偏请求消耗物理预算但不产生第二次逻辑纠偏。不得靠新 Plan、换工具或新 Attempt 恢复此机会 |
| 总 deadline | 包括排队、退避、暂停；resume/自动重试不延期。显式人工续期只能经独立授权与审计，不能默认为新的预算或清空历史 |

物理发送前在短事务内校验执行权、停止状态和预算，并原子预留；不持数据库锁调用远端。确定尚未发出才可撤销预留；已发送但用量未知保持保守预留/待对账，不能因超时退款。Token/费用硬上限需要预留可验证的输入量及受控最大输出；未知计价或 Provider 不支持可靠输出约束时不能宣称严格费用硬界。迟到回执可结算原预留，但不能恢复旧执行权。重放成功回执不新增物理费用。

Checkpoint 仅携带账本版本/引用，不能用其计数覆盖平台较新的累计值；落后时按账本对账，缺必要记录则阻断，不按零开始。并行分支共享 Run 预算，不能每个分支各拿完整上限。跨分片、进程重启、失租接管、业务失败重试、显式同 Run 重试均遵循此规则。需要额外额度时另记经授权的追加额度及理由，保留原始上限和累计消耗，不能隐式“重新初始化”。新 Run/fork 关联来源且重新准入，禁止自动通过创建子 Run 绕过额度；未来自动子 Agent 须共享父预算或预留子预算后才开放。

#### 什么是重复，什么是真进展

动作指纹包含工具/能力、规范化参数、业务主体及知识/工具快照；结果指纹包含受信回执的业务内容及有效性。参数按 Schema 规范化对象键序，不擅自排序有语义的数组、不去除金额/单位/时间范围。仅剔除显式声明的无语义字段；禁止用新 Trace ID、时间戳或模型换一种措辞制造新结果。跨工具等价仅使用冻结的能力映射，不能凭工具名相似推定等价。

进展是“新增且有效的业务事实、缺失项被补齐、矛盾被解决或受信外部任务状态改变”。采购 P-17 的事实至少区分审批、预算、报价有效期、准入和签署权限；其他订单回执不构成进展。摘要变化、再次命中同一证据、重复空结果、重复错误、模型声称完成都不算。有效性在使用时重验，撤权/过期要使已有支持失效；因此进展不能仅靠累计证据数量判定。通用语义判断可提供辅助信号，但不依赖另一个 LLM 单独授予继续执行权。

初始策略（版本化试点值，需金标校准）：保存最近 8 个已决策逻辑动作及结果摘要；相同动作成功得到相同结果两次后，第三次提议触发检测；周期 2–3 的相同动作/结果序列重复两轮且无事实进展时触发；连续 6 个完成的逻辑动作无进展也触发。超过检测窗口的长周期由 Run 总预算兜底。并行结果按分支顺序与因果关系判断，不把无因果关系的完成顺序拼成 ABAB；共同预算和事实进展仍由 Run 聚合。

正常有据分页（新游标/新条目）、分批取证、工具声明的外部任务轮询不是直接重复；轮询必须有受信 taskId、最小间隔、次数和总截止时间，无状态变化时挂起等待。QUOTA/SLICE/退避没有新结果，不计语义无进展次数，也不能清空历史；deadline 仍消耗，控制面轮询须限频、退避，禁止零间隔忙循环。技术重试与语义新动作分开计数，改变 operationId 不能逃避动作指纹比较。

#### 检测、纠偏和停止如何持久化

1. 保存当前动作意图后、任何新外呼前，调用治理判定；判定以 operationId + requestDigest + 事实版本幂等，记录参与比较的回执引用。已有成功回执走只读恢复，不重调远端、不重复累计检测事件。
2. 首次无进展时先原子登记唯一纠偏机会，再由显式图节点请求模型列出缺失事实并选择不同策略；该调用仍须获得剩余物理预算。不是在 Java 网关中隐藏调用循环。提交后丢 ACK 只恢复同一判定，不能再授予纠偏。
3. 纠偏后再次触发、无纠偏额度或预算不足时，持久化停止原因 LOOP_DETECTED / NO_PROGRESS / BUDGET_EXHAUSTED，并拒绝后续探索和旧代次调用。结果候选、摘要和新 Plan 均不能解除停止裁决。
4. 图将停止信号转换为持久终态观察；平台同时提供不依赖图继续调用模型的收尾扫描，防止“预算耗尽后无法生成答案”或 Worker 宕机导致 Run 永久 RUNNING。按冻结失败策略保持原节点或转人工；不得伪造肯定答案、清空结果当成功，P-17 应进入 MANUAL_REVIEW。纯缺资料题按既有 ABSTAIN 策略处理，不能和技术循环混为一谈。
5. 停止后撤销执行资格并结束业务 Attempt；图槽位/连接在退出后释放，outstanding 随实际终态结算。仍未知的外呼保持隔离许可，只能由可信对账释放。平台终态不等于远端请求已经结束。

#### 交付和方案复核门禁

- **第一批必须实现：** Run 预算账本及并发预留、同 Run 所有恢复入口不重置、确定性重复/短周期检测、持久停止和无模型收尾；冻结策略版本、记录结构化原因，不先做复杂语义评委。
- **第二批：** 一次纠偏节点、业务事实适配器、外部任务轮询例外、并行分支合并。未完成纠偏时直接保守交人工，不假称自愈；未验证的例外不开放。
- **E0 离线判卷：** AA、ABAB、ABCABC、换 operationId/改 JSON 键序、随机 Trace 字段、重复空值必须识别；真实分页、独立并行取证及新增有效事实不得误报。需要多步才能得出结论的题也要纳入，不能以调用多就判循环。
- **G1 恢复验收：** 在预留/发送/回执/判定/纠偏各提交边界丢 ACK 和重启；分片大小改为 1、压缩上下文、换 Attempt/代次、重放旧 Checkpoint 后，总消耗不减少、纠偏最多一次、既有回执不重复扣费。
- **G2 故障与并发：** 两分支竞争最后一次额度只允许一个发送；未知请求不退款；停止与迟到候选竞争不得放行；Run deadline 到期且无 ACK 也必须终结并交接。持续 QUOTA 等待验证 RPC 有界、资源不增长。
- **P-17 联合验收扩展：** 模型交替请求政策与订单但始终无新事实，预期停止并到 MANUAL_REVIEW；对照政策与实时状态各取一次且事实齐全，仍可到 READY_CHECK。分别检查工具轨迹、停止原因、实际历史/活动节点与零副作用。报告误报率、漏报样例、停止前调用数及恢复前后账本，不以“最终没超时”代替验收。

复核结论：该方案不新增图游标；检测错误的最坏自动动作是停止/交人工，而不是授权推进。片段重置与 Run 总账分离、缓存恢复与物理调用分离、容量等待与语义无进展分离。仍需在实现评审验证归一化字段白名单、事实新颖性适配器、账本事务竞争和所有重试入口；缺任一硬预算或终态收尾证据，不得宣称防循环已完成。

### 5.2 可选 Plan 与计划校验（已实现初始规划与一次修订）

2026-11-20 实现：V74 的初始规划之后，V76 为策略 v2 增加循环触发的一次 revision 1 → 2 修订，共享 Run 唯一纠偏许可；事务验收和发送前版本复核已接入。本节通用重规划及并行分支仍为目标设计，当前边界见[修订验收](../quality/graph-plan-revision-regression.md)。

Plan 是受约束的行动建议，不是业务规则、授权、图代码或完成证明。ROUTE 选能力范围、MODEL 逐轮提议动作本身不等于显式 Plan；PLANNED 首版通过独立规划与验收节点建立该边界。AgentVersion 冻结 planningMode、Plan Schema、任务契约、校验策略及预算版本；Run 固定引用，不在恢复时套用最新模板。

| 模式 | 适用场景 | 行为 |
| --- | --- | --- |
| REACTIVE | 简单查询或逐轮决策 | 无额外规划模型调用，仍执行权限、任务契约、预算和无进展检查 |
| CHECKLIST | 已知核验规则，如 P-17 | 平台从审核发布的任务契约生成必要事实清单；模型只选择取证方式，不自行删除核验条件 |
| PLANNED | 需要动态拆解的开放任务 | 经 MODEL 网关生成结构化 Plan，校验并持久化通过后，图才按约束选择动作 |

默认不为所有任务增加模型调用。P-17 优先 CHECKLIST；只在对照实验中启用 PLANNED，比较收益和额外 Token/延迟。三种模式都不能绕过最终结果验收。

#### 权威任务契约与计划内容

任务契约由平台审核发布，包含 subjectBindings、requiredFactIds、allowedCapabilities、forbiddenActions、acceptanceRules 和 failureDisposition。它规定“必须证明什么”，不编码内部 nextStep。来自知识文档的抽取条件仅为候选：绑定有效原件/版本/引用并经审核后才成为高风险业务规则；未经审核不支持自动放行。运行时知识冲突或撤权应阻断并复核，而非静默沿用失效规则。

Plan 至少包含 planId/revision、parentRevision、taskContractRef、subjectRefs、goal、steps[]；每个 step 包含稳定 stepId、factIds、capabilityChoices、dependsOn、successRuleRefs 和 missingEvidenceAction。完成条件必须引用平台允许的规则，不能接受模型生成脚本、SQL、表达式或任意服务 URL。stepId 是计划条目标识，不替代工具 operationId、审计 Step 或图节点 ID。计划不能增加新业务主体、工具权限或自动创建子 Run。

#### 三层校验与落地顺序

1. **结构校验：** Schema、必填/枚举、大小/深度/步骤数上限、唯一 ID、依赖存在且无环；在有界复杂度内完成。结构合法不代表业务正确。
2. **业务校验：** 主体必须对应输入；必要事实全部覆盖；禁止动作不可出现；能力在冻结工具集合内且当前仍授权；完成/失败规则不得弱化任务契约。可行性不足或预算不足不能批准成可执行计划。模型预测调用数仅用于估算，实际外呼仍逐次扣账。
3. **执行校验：** 后续每个动作关联已接受的计划版本及条目，校验前置事实、主体、工具和当前授权。条目只有被有效回执/证据支持后才能标完成；模型声明“已完成”无效。最终候选独立校验全部必要事实，不只看 Plan 是否全打勾。

显式图顺序为：任务契约加载 → PLAN 生成（仅 PLANNED）→ 确定性计划校验 → 持久化接受回执 → 动作选择/执行 → 事实更新 → 最终校验。Java 只提供受治理的单次调用与确定性门禁，不在网关中隐藏规划/修复循环。计划通过之前不执行其业务工具；确需预取规则的场景只能走独立批准的只读引导阶段，也计入预算和历史，不能用无约束查询“先准备一下”。

计划执行状态由图保存；平台保存不可变计划正文或引用、摘要和接受/拒绝回执，不据此维护第二套步骤调度。Checkpoint 保存已接受 revision 及回执引用，恢复先校验 Run/版本/摘要/授权。若接受回执已提交而图 Checkpoint 丢失，按稳定规划 operationId 恢复原计划，不再生成另一份并重复扣逻辑次数。

#### 与无进展和预算衔接

- 初始规划、格式修复、重新规划、审查模型全部走统一 Model Gateway 计入总预算。不能在 PLAN 内放不计量的子循环。格式修复和语义重新规划共享 §5.1 的全 Run 一次自动纠偏机会（试点默认），不得各自再分配一次；物理重试另扣外呼预算。
- 新 plan revision 必须记录调整原因与新增证据引用。只换描述、stepId、顺序或改名不构成进展；检测依据业务事实和动作/结果指纹，不以 Plan 版本切断历史。新计划不能丢弃未满足条件，旧结果仅在来源、主体、权限和有效期仍匹配时可复用。
- 首次检测进入受限“待纠偏”状态，不是终态停止：仅允许那一次已登记的纠偏操作及其有预算重试/回执恢复，普通探索暂不放行。最终 LOOP_DETECTED / NO_PROGRESS / BUDGET_EXHAUSTED 停止后不再允许新规划；明确区分这两种状态，避免纠偏被自身门禁拦截或终态被重新规划解除。
- 并行分支只能读取同一个已接受计划版本。初版仅在无在途旧计划业务调用的安全边界切换 revision；切换采用期望旧 revision 的条件更新。晚到旧结果保留审计，经过原始绑定和当前规则核验后才可复用，不能直接把新计划条目标完成。
- 不可判定的开放任务计划只能标为“通过结构/权限检查”，不能宣称语义正确。第二个 LLM 审核仅提供建议；高风险动作仍需独立业务规则或人工批准。停止/拒绝无须追加一次模型调用，直接按冻结失败策略交接。

#### 交付、验收和整体审查

先完成 §5.1 硬预算与终态收尾，再落地 CHECKLIST 和最小事实校验适配器；之后才开放 PLANNED 与计划版本切换。2026-11-20 已先实现 CHECKLIST 下循环触发的一次纠偏；V76 已接入一次计划重新规划；格式修复尚未接入，未来必须共享该 Run 额度。若事实适配器未完成，只能报告“可观测结果重复”而非“已证明没有业务进展”，按保守策略交人工。审核文档抽取、复杂并行计划和泛化语义评委为后续扩展，不阻塞固定业务试点。

联合门禁新增：P-17 计划漏预算、换 P-18、擅自扣款、删除失败条目、伪造完成、无效依赖和循环依赖全部拒绝；合法不同取证顺序可通过。格式修复后又要求重新规划不得重获纠偏额度；换 Plan/Attempt、分片恢复或旧 checkpoint 回放不得降低累计预算/清空无进展历史。计划接受丢 ACK 不重复生成，纠偏提交后宕机不重复授权；并行旧版本结果不得覆盖新版本。比较 REACTIVE/CHECKLIST/PLANNED 时固定模型、权限、快照和用例，报告任务通过率、循环误判/漏判、额外调用与成本，不把计划文本美观当作收益。

整体复核结论：Plan 不改变 Run/Attempt 层级，不增加通用调度器，不授予工具权限；任务契约、真实证据、Run 预算和最终 Flowable 门禁保持权威。已补齐“模型定义自己验收条件”“新计划清空历史”“纠偏套娃”“接受丢 ACK 重新生成”“并行旧计划污染”“预算耗尽无法收尾”六类设计风险。语义正确性无法由 Schema 保证，必须保留未知/拒绝/人工路径；上述为待实现契约，仍须按故障和同 Run 联合验收证明。

## 6. 容量、公平及长等待

Java 负责业务准入、图启动/恢复命令、模型/工具调用许可；Python 有界 Worker 消费运行资格，LangGraph 负责图内推进和恢复。命令队列不是图节点任务队列，OSS 图库不提供平台公平分配。详细配额权威与指标见[资源治理](agent-resource-governance.md)。

- 平台/租户 outstanding 有界且包含暂停 Run；全局/租户/供应商账户模型/连接器在途分别限制。幂等重复不再占位；超额明确拒绝。Flowable 内准入失败回滚本次推进，不能留下无 Run 的等待节点。
- 按租户公平分配业务启动和受限调用；共享凭据下多个 Provider ID 归入同一额度域。现有 MCP Redis 治理在统一切换前保留，不双扣同一许可。
- 无调用资格返回类型化等待与稳定 waitRequestId，图在恢复边界持久挂起。Java 只排“线程何时有资格恢复”，不存 nextStep；等待登记/图挂起竞态靠事实核对，丢唤醒靠扫描。
- 每次等待节点调用只触发一个 interrupt；恢复后资格失效则持久化新的等待状态，经图边再次进入等待节点，不在同一节点累积 `while + interrupt` 的历史恢复序列。等待前登记和恢复命令均幂等。
- 必须验证挂起**确实释放执行槽**；async、虚拟线程或 interrupt 字样不是证明。恢复资格过期允许再等待，但无忙循环；上游图队列也有界，无资格线程不能挤满 runtime。
- Python 异步 I/O、受控 Java 虚拟线程降低阻塞成本，连接、CPU、响应体和 checkpoint 均有上限。外呼在途仍占许可；远端状态未知进入隔离额度，不凭本地 TTL 视为远端结束。

## 7. 接管、撤权和安全

### 7.1 租约过期但 Checkpoint 会话锁未释放（2026-11-16，待实现）

**问题与边界。** Java generation/租约保护业务调用与结果提交，Checkpoint 数据库会话锁保护同一 thread 的图状态写入。两者不是同一把锁：Java 租约过期不会释放 PostgreSQL 会话锁。旧进程仍存活、外呼阻塞或网络半开时，新 Worker 可能持续 RuntimeBusy。当前同连接、不自动重连的 saver 能防双写，但尚不能保证有界接管时延；禁止以“租约已过期”作为绕过数据库锁的理由。

**官方语义核对。** PostgreSQL [会话 advisory lock](https://www.postgresql.org/docs/18/explicit-locking.html#ADVISORY-LOCKS) 随显式释放或会话结束释放，不随业务 TTL 或事务回滚释放。[pg_cancel_backend 与 pg_terminate_backend](https://www.postgresql.org/docs/18/functions-admin.html#FUNCTIONS-ADMIN-SIGNAL) 分别取消查询和终止会话，取消查询不等于释放会话锁。statement_timeout/lock_timeout 约束语句或锁等待，不能限制 idle 会话持锁总时长；[idle_session_timeout](https://www.postgresql.org/docs/18/runtime-config-client.html) 可能把等待模型的正常连接一并关闭，不能简单设置为租约时长。网络故障检测和驱动读取截止须部署实测，不能把连接建立超时当作所有 I/O 的硬截止。

#### 安全接管协议

1. **确认并冻结旧权威。** 受信协调者用数据库时间、期望旧 generation 的条件更新登记 takeoverId，撤销旧 capability，并阻止普通 claim 在处置期间反复生成新代次。控制面不可达或不能证明旧权威失效时，禁止自动杀会话；旧执行者失租后也应保守停止新调用。
2. **合作退出。** 请求旧 Worker 停止，设置失租标记；已有外呼不伪装取消。在配置的宽限时间内等待其返回并退出图作用域，关闭 saver 连接后才交接。宽限、外呼超时、DB I/O 超时及总 deadline 分别记录，不用线程强杀冒充可控退出。
3. **核实残留持有者。** checkpoint 连接获得锁后、图第一次读写前，必须经受信控制通道登记 session 身份：数据库部署/主节点身份、数据库、专用角色、backend PID + backend_start、thread/锁键、Worker 实例、generation 和连接随机标识。登记失败立即关闭，不继续执行。application_name 仅帮助观测，不作授权依据；禁止仅凭 PID、锁等待时间或 Run ID 杀连接。锁已消失则跳过终止；残留 owner 缺登记或身份不一致转运维，不猜测。
4. **有界升级处置。** 初版只提供受限运维审批，不开放通用 kill API。专用处置服务重新核对旧权威、会话身份和锁持有事实，仅针对该旧会话执行终止；不能授予普通 Worker、租户管理员或图运行账号广泛 pg_signal_backend 权限。PID 会复用，单次“先 SELECT 再 terminate(pid)”存在检查与执行竞态，不能宣称原子安全。只有部署能约束连接角色/实例并证明目标不可能换成新 owner 时才允许自动化；无法证明则保持阻断，由数据库运维处理。终止旧 Worker 进程也需平台实例身份核验，不能误杀承载其他任务的整个共享进程。
5. **确认释放后授予接管。** 终止调用返回或控制 RPC 超时均不算接管成功；必须确认原会话结束，并由后继者在正式 saver 的同一连接上取得原锁。仍忙则持久退避、释放本地连接/槽位并报警，不忙重试、不生成随机 thread、不复制一份图逃避锁。取得后再核验当前 generation、Run 非终态和 deadline，再读取最新 checkpoint；读取候选/工具引用时复核权威回执，不信任失租后仅落到图中的旧状态。
6. **处置可恢复。** takeoverId 及请求、结果和核验记录持久化；协调者重启后重新查询事实，不盲目重放终止 PID。重复处置幂等，不重置 Attempt、Run 预算、Plan 或无进展历史。超过接管处置上限，保持禁止执行并交运维；总 deadline 到期由平台无模型收尾路径结束 Run，不无限等待图 ACK。

以上是执行权恢复协议，不是图节点状态机。当前 claim 即轮换 generation 的接口需要配套处置屏障与“锁已取得”确认后才能启用自动升级处置；此门禁未实现前维持 RuntimeBusy + 有界退避，不声称已经支持自动强制接管。

#### 资源释放必须分别确认

| 资源 | 释放依据 |
| --- | --- |
| 旧 Worker 本地线程/槽位 | 实际执行退出；不能只改数据库计数便认为线程已停止 |
| Checkpoint 连接/锁 | 原连接关闭或数据库会话确实结束；新连接不得自动沿用旧 saver |
| 图执行许可 | 撤销后只阻断后续授权；残留旧执行单独记录，不以逻辑活跃数冒充实际资源数 |
| 外呼 Permit/费用预留 | 明确未发送、可信完成/取消证明或回执结算；旧 DB 会话终止不能证明远端模型/工具已停止，未知仍隔离 |
| outstanding | Run 按业务终态结算；挂起或接管等待不释放，不等于批准继续流程 |

每 Run 最多一个受信处置流程；全局/租户限制处置并发、残留会话和未知请求量，阈值触发准入降载。看门狗和运维查询使用独立的小容量连接预算，不能依赖已经耗尽的业务连接池。上报 lease-expired-to-lock-release、lock-busy 年龄、失租仍在途数、处置成功/失败、未知额度及实际线程/连接数；高基数身份进受控审计，不作为指标标签。

#### 验收与整体复核

- 保持旧 DB 会话存活，仅中断 Java 心跳：新 Worker 不双写，旧 Worker 返回后关闭连接，新代次恢复同一 checkpoint。
- 旧 Worker 永久阻塞、DB 网络半开、数据库重启、控制面不可达分别注入；区分可自动恢复与需人工处置，记录实际时延而非只断言最终成功。
- 旧会话恰好自行退出、PID 复用、新 owner 竞争、错误 thread/角色/数据库、重复 takeover 请求均不得误终止新执行或其他租户；身份无法证明时拒绝处置。
- 终止 RPC 丢 ACK、协调者重启必须重新核验；旧 saver 写入失败且不重连，旧代次模型响应不能推进业务。已提交有效回执可恢复，未知外部副作用不重发。
- 持锁期间 deadline 到期能独立收尾 Run；重复 RuntimeBusy 不泄漏连接、不消耗新的业务 Attempt、不重置预算。持续分区下残留资源达到阈值后明确背压，不能宣称分区期间仍保证无条件可用。

复核结论：安全优先于接管速度；已明确“撤执行权、确认旧存储写入者退出、后继独占、再次校验”四步不可省略。最大的剩余实现风险是身份登记窗口、PID 检查竞态和底层 I/O 无硬截止；初版保守运维接管，不把查询取消、TTL 或 kill 返回值当作释放证明。若部署无法实现安全且有界的会话处置，再评估兼容官方 saver 的存储侧代次隔离方案；不得只在 Java 检查 generation 就宣称图存储已被隔离。

图线程互斥和迟到检查点防护通过官方 saver 同会话所有权外围保护验证，不声称开源库自带分布式租约。Java 不能因轮询超时另启竞争执行，先查询/取消/核对原执行，再按后端接管契约恢复。存活的数据库所有者未退出时，后继者收到忙状态而非强抢；数据库失联网络分区与有界取消仍列入 G2。

平台 executionSessionGeneration 拒绝过代调用授权与候选提交，**不替代图存储 fencing**。若旧 Worker 能污染最新图检查点，接入门禁失败、禁止自动接管；不能增加 Java nextStep 掩盖。存储写入条件、网络分区、旧 Worker 复活都要实测。

图持久化空间与 Java RLS 是不同边界。用户只访问 Java，不可自选 threadId 或访问管理接口。服务间用短期、受众受限的执行身份；模型/工具调用、回执复用、原文读取、最终验收均重验当前权限，冻结版本不是永久授权。

撤权后旧摘要可能含敏感内容，不能只过滤新调用就发送整个旧上下文。须重建可证明授权的上下文，否则终止或人工接管；网关不能信任图自报“引用已验证”，须核对平台登记的来源/操作与原回执。取消/deadline 后阻断新调用与成功完成；迟到结果只审计/结算，不改终态。服务存储的密钥、备份、租户映射、加密及保留删除策略纳入验收。

## 12. 整图命令与执行身份持久层（2026-11-11）

## 13. 模型原响应与确定性校验接入（V66，2026-11-11）

`GraphCognitionGateway` 已复用既有 Provider 端口完成单次模型调用；`JdbcGraphCognitionStore` 持久化原响应、候选/工具决策和校验回执。它不运行 Agent 循环，图决定下一次 MODEL/TOOL/VALIDATE；原生执行器没有被套壳调用。

- 模型操作按逻辑编号及完整输入引用历史核验，物理调用次数单独累计。相同代次的并发请求返回执行中；原响应已保存则恢复解释而不重答。原响应尚未保存的外部不确定窗口仍可能重复计费，不能宣称外部模型 exactly-once。
- 原响应先提交，参数引用和模型回执随后原子发布。证据、候选和模型回执不能串 Run；已产生候选后不能再新建模型操作改答。原始模型响应、已完成回执和校验结论不可重写。
- `AgentCandidateValidator` 与原生执行器共用拒绝、Schema、禁止把工具命令当答案的门禁；`TaskMemory.Context` 解耦执行框架，复用现有主体/决策/CitationClaim 证据校验。校验失败不会调用模型修复，也不会推进 Flowable。
- 真实 Python 图 → 有界 HTTP → JDBC 执行身份/引用/模型回执 → Registry 链路已验证。模型替身固定返回工具调用再答案，依次丢掉候选和校验回复，再打开 PostgreSQL 图恢复，模型 2 次、工具 1 次、校验回执 1 条，Java Run 仍未成功提交。
