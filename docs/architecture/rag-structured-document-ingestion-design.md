## 1. 决策、背景与非目标

选用 **LangChain4j + MinerU + 现有 PostgreSQL/pgvector**。LangChain4j 负责 Java AI 基础设施复用，MinerU 负责专业文档解析，平台继续持有权限、版本、任务、证据和流程语义。不引入 RAGFlow 作为第二套知识管理系统，不自研 OCR、版面识别或表格识别模型。

当前文本/Markdown、方舟 Embedding、pgvector 精确向量检索及 RRF 混合检索已有本地链路验证；`TextChunker` 仍是文本切分，尚无 MinerU 适配器、PDF 二进制上传、结构化图表摄取和原图引用浏览能力。最终答案 Grounding 与发布级评测也未完成。选型不会自动补齐这些能力。

备选取舍：自行编写治理与结构归一化是必要的，但从零开发 OCR/表格算法成本过高；RAGFlow 自托管后可通过 API 调用，但会引入额外知识生命周期权威；Docling 可作为未来替换适配器，当前先集中验证 MinerU，不并行维护两套生产解析器。此选择不是对所有文档质量、部署成本或市场占有率的排序。

首期目标是声明支持范围内的原生/扫描 PDF、中文混排、表格及跨页续表、图像与图题的结构化摄取。图像先提供原始资产、OCR/图题和可追溯派生描述；不承诺任意跨页大图拼接、图表数值精确推断、像素级问答、多模态向量检索或音视频索引。识别不清的关系不能猜测为确定证据。

## 2. 责任与依赖边界

```text
平台上传与原件存储 → 持久化 IngestionJob / Lease
  → DocumentParserPort → MinerU 独立解析服务
  → 平台归一化结构 + 资产清单 + 解析质量检查
  → 结构感知 Chunk → EmbeddingModelPort → VectorIndexPort
  → 候选 IndexVersion 完整性校验与原子激活
  → Profile / AgentVersion 显式发布绑定
  → 授权检索 / 融合 / 可选重排 → Evidence / Citation
  → Agent → GroundingPolicy → Flowable
```

以上 `DocumentParserPort` 及下文解析对象是**目标契约名称**，不表示已有同名实现。MinerU 以独立进程/HTTP 服务隔离 Python、模型、资源和升级，不获得平台数据库、租户授权或流程推进权限。服务地址由管理员配置且受出站策略约束，模型不能指定解析端点或原件 URL。

| 责任 | 承载方 | 约束 |
| --- | --- | --- |
| 布局、阅读顺序、OCR、表格/图像提取 | MinerU 适配器 | 版本/模型/配置固定，保留原始输出；能力须用本项目样本确认 |
| 通用文本切分、Embedding/模型、聚合与重排集成 | LangChain4j 基础设施适配 | 先验证项目固定版本 1.20.1 的兼容性；线上新版本示例不能直接套用 |
| 结构归一化、富结构切分与来源关联 | knowledge-engine 应用端口与适配器 | 不向领域层暴露 MinerU JSON、Python DTO 或 LangChain4j 类型 |
| 原件、权限、版本、租约、幂等、索引发布、Trace/Grounding | 平台 | 不交给解析器或 SDK 作为权威；不改 AgentRun/Flowable 协议 |

LangChain4j 已提供通用切分、RRF 聚合与 ScoringModel 重排扩展，优先评估复用，不长期另造等价通用组件。但当前平台 RRF 不是因此已被替换；适配必须证明授权过滤、排序/分数语义、Evidence 身份和超时边界等价。表格行列切分与来源关联仍需平台的结构感知策略，不能简单用字符切分器代替。

## 3. 原件、结构与资产契约

原始二进制不可变保存，记录 MIME、字节数、原件 SHA-256、页数和存储引用。**原件哈希与现有规范化正文哈希不是同一个概念**：保留现有文本 BOM/换行规范化规则，不改历史指纹；PDF 原件、解析输出、派生文本和资产分别计算摘要并互相关联。

目标中立模型：

```text
DocumentVersion → OriginalArtifact {hash, mime, storageRef}
  → ParseArtifact {recipeVersion, status, pageCoverage, warnings, manifestHash}
    ├─ TextBlock {elementId, headingPath, text, pageRegions, readingOrder}
    ├─ Table {elementId, caption, headers, rows, cells, units, footnotes,
    │          rowSpan/colSpan, pageRegions, continuationLinks}
    └─ Figure {elementId, assetRef/hash, caption, derivedDescription,
                pageRegions, relatedElementIds}
  → Chunk {parentElementIds, locator, representationVersion, contentHash}
  → IndexVersion → RetrievalProfileVersion → AgentVersion
```

`pageRegions` 保存原 PDF 页序及区域坐标和坐标系；跨页对象允许多个区域，页标显示与机器索引转换需明确。元素 ID 在同一解析产物内稳定，重解析后通过新 artifact/recipe 关联，不要求算法变更后 ID 仍相同。Citation 可回到原件版本、页、表/行列或图区域，不能只落到临时 Markdown 偏移。

必须保存结构化结果、资产清单和必要的解析原始产物，Markdown 只是导出/检索表示之一。只存 Markdown 会丢失合并单元格、区域坐标与图表关联。资产引用必须按返回清单校验，不拼接猜测输出目录；远程 URL、文件路径和压缩包成员均不可信。

OCR/视觉模型生成的文字、图像描述和推断的跨页关联属于**派生产物**，记录模型/配置、来源区域和异常/置信信息（解析器实际提供时）；不捏造置信分数，不提升为人工批准的原文。是否足以支持关键业务结论由 Grounding 与审核规则决定。

### 结构感知切分

- 正文按标题层级、段落与阅读顺序切分，再采用有界长度/重叠；保留 parent/section 和页区域。
- 表格按语义行组形成子块，携带对应表头、单位、必要脚注和表 ID；保留完整父表及单元格定位。不能将一行数据脱离表头后作为完整规则。
- 跨页续表须保留重复表头处理、边界断行、合并单元格及源区域映射。相邻同列数的两张独立表是必须拒绝错合并的负例；关联不确定时分开并告警/复核，不静默合并。
- 图像保留原件裁剪和图题关联；派生描述单独标记。跨页图题可以建立带来源的关联，不意味着任意跨页图形已被重建。
- 不能无界向 Prompt 注入整表/原图；按冻结策略选择受控文本和引用，超大对象使用同租户受权资产引用。未实现的模态必须明确 `PARTIAL`/拒答，不以文本召回成功掩盖关键图片未解析。

2026-11-03 检索讨论收口：入库统一保留父子/邻接/来源关系；建议性搜索可按普通块返回，驱动型检索按冻结策略将命中节点与有界父块、邻句去重组成证据组，重排启用时以组为单位，避免单位/条件单独竞争 TopK 后被丢弃。**扩展仅作用于召回命中后取回的信息，不能补救完全未召回的内容。** 父块是否独立参与召回与是否作扩展上下文分开设计，不预设首版只能索引子块；语义复杂分类不是前置条件，结构/重叠也不保证所有隐含依赖被发现。策略、分数、预算与对照验收统一见[实施设计第 8 节](rag-structured-document-implementation-design.md#8-结构感知切分检索与-citation)，均尚未实现。

## 4. 版本、任务与发布一致性

解析 recipe 固定：MinerU 包/容器摘要、模型与权重版本/摘要、后端/tier、OCR 语言、页范围、预处理/后处理开关、外部模型引用和归一化版本。Chunker、Embedding 模型/维度/Query-Corpus 配置也分别冻结。任一变化产生新的 ParseArtifact 和候选 IndexVersion；不原地改旧文档、已发布 Profile 或 AgentVersion。

原件上传需要受权限保护的二进制入口、独立存储和配额；不能把 PDF 当字符串塞入现有文本 `content` API。事务内登记版本/任务，提交后执行网络解析；不持数据库锁等待模型或解析服务。外部调用使用共享绝对截止时间、页/输出预算及有界并发，完成后由短事务验证任务 owner、Attempt/fencing 和有效租约再写进度/终态。

解析幂等身份至少由租户、documentVersion、原件哈希和 recipe 确定。若服务支持异步任务，持久化远端任务回执与状态；丢响应先对账，不能盲目重复创建。若锁定版本仅支持同步接口，则由平台保存阶段与幂等产物，失败重新计算可接受但不得重复发布。重启后恢复不能依赖内存会话。远端“成功”不是平台索引成功；迟到 Worker 即使完成解析也不能激活索引或覆盖新 Attempt。

发布前确认预期页全部覆盖、资产哈希/引用完整、关键表头/单位/来源可定位、向量和候选来源快照完整。解析器分页/预算截断必须显式处理到结束，禁止默认只解析前几页后声称全文。失败、缺页或关键结构不确定阻断自动激活；若允许人工批准降级，须固定策略、声明缺失范围并留审计，不能降级成无警告的 `SUCCESS`。

索引激活继续复用现有完整来源快照与原子任务完成机制；新解析服务不能引入另一套索引发布协议。删除/禁用/撤权先阻止在线读取，清理按保留策略覆盖原件、资产、派生文本、向量、缓存及 Trace 引用；历史可重放与法定删除冲突必须明确记录，不绕过当前授权。

## 5. 部署、安全与可运营性

本次不安装依赖、不部署服务、不选择未经实测的 MinerU 版本。D0 必须锁定可复现版本、模型、API 请求/结果样本及部署资源预算；CPU/GPU、中文扫描质量、峰值内存、延迟与吞吐用试点数据决定，不能以“能启动”作为生产容量结论。

- 解析进程按任务隔离临时目录和文件权限；限制文件/MIME、页数、像素、总耗时、CPU/内存、解压后字节数/成员数、结果大小和租户并发。加密、损坏、恶意、超限文档返回稳定错误类别。
- 防 Zip Slip、绝对路径、目录穿越、符号链接、嵌入脚本、HTML/SVG 外链及 SSRF；资产访问复核租户/知识范围，不能直接公开解析器目录。
- 文档及 OCR 中的指令均是不可信数据，不能改变系统指令、租户、工具权限或审核结果。敏感原文/凭证不进日志或模型无界上下文。
- 本地部署不自动等于离线：可选 LLM 辅助 OCR/表格单元格合并及 Embedding/聊天可能出站。模型地址、凭据引用和数据出站须显式批准；无配置不得静默调用云服务兜底。
- 类型化区分临时不可用/超时与认证、格式、不支持、质量不完整；有界重试、恢复/取消、人工复核和垃圾产物回收，未知错误不默认为成功。
- 记录低基数任务积压、解析时延/失败类别、缺页/结构告警、资源/配额拒绝和派生资产清理；业务 ID 放 Trace，不作指标标签。
- **许可证门禁**：按锁定版本审查 MinerU 代码及模型权重/外部模型条款。当前官方许可证包含附加条件，不得概称纯 Apache-2.0；旧版本也可能不同。商业部署前确认归属声明、使用条件和模型授权，不以本设计替代合规审查。

## 6. 交付顺序与验收

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| D0 选型落地设计 | 固定版本/模型/许可、API 样本、结构契约、困难 PDF 与资源试点 | 可复现解析结果及能力清单经审查；本次仅完成选型和方案，不宣称 D0 全部完成 |
| D1 解析与产物 | 原件存储/上传、MinerU Adapter、结构归一化、任务恢复和资产权限 | 完整页覆盖、幂等/迟到拒绝、超限/损坏/跨租户负例通过 |
| D2 结构检索 | 富结构 Chunk、资产定位、索引构建/删除传播、API/前端预览与 Citation | 表头/单位/脚注和页区域可追溯，旧 Profile 不受新解析 recipe 影响 |
| D3 业务闭环 | Agent 工具证据、逐结论 Grounding、拒答/人工、Flowable 与恢复等价 | 固定 PDF 样本端到端回归，质量/权限/故障报告可复现；结合评测 E1/E2 发布 |

与[评测专项 E0–E3](rag-evaluation-and-routing-delivery-plan.md)协作：既有文本 E0 契约/试点可并行，不必等十领域数百条全部生成；PDF 的正式 E1 比较须先通过 D1/D2 的结构质量门禁。先固定解析方案，再同快照比较检索，避免同时更换解析、模型和排序而无法归因。Rerank/动态路由仍需基线收益证明，不因接入 MinerU 自动启用。

固定验收样本至少覆盖：原生与扫描中文 PDF、多栏阅读顺序；跨页续表、重复表头、断行、合并单元格、单位/脚注与相邻独立表负例；图题跨页、低清/旋转扫描和图片中恶意指令；加密/损坏/超页数/超像素/超大结果；资产缺失/哈希冲突、删除/撤权、跨租户；超时断网、Worker 强杀、旧 Attempt 迟到和重复提交。为每个样本保存权利来源、原件哈希、期望结构/页区域与审核结论，不手工改写掉难点以提高成绩。

分层报告文字/阅读顺序、表格结构与续表关联、图题关联、来源定位、检索 Recall/引用、最终 Claim/Grounding，以及 P95/内存/成本和恢复等价。审核样本中的静默错合并、丢失决定性单位/表头、跨租户结果和重复激活均硬阻断。其余数值阈值在试点后按领域风险签署版本；不能凭空给生产质量打分。解析通过不等于答案正确，现有 P0/Runtime 生产门禁也不因此豁免。
