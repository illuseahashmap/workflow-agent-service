## 长期修复

1. 输出 Schema 增加可选 `x-workflow-evidence`。发布时核对实际工具、输入主体和已发布检索 profile 的审核条款；每个决策必须显式属于事实约束或安全弃答集合，不能漏配后自动放行。
2. 最终门禁同时校验真实检索引用、输入主体、工具参数、原始回执主体及必要事实。缺失、串单、矛盾证据不能被模型摘要、格式修复或自由文本补足。原生与图端共用同一门禁，冷恢复从受验证回执重建。
3. 给模型提供有界的原始字段投影及缺失引用列表。新契约的原生结构化任务不再调用可选模型摘要，避免增加延迟和引入二次语义改写；既有版本摘要策略保留。
4. 增加严格 oneOf，约束 action/decision 合法组合；P-17 的肯定判断、补资料、人工处理分别有一致的输出契约。
5. v2 图对永久 Provider 错误持久停止，由既有完成服务和 Outbox 无模型收尾。v1 wire 保持原行为，暂时性错误保留重试语义。未知物理调用许可不会因停止被擅自释放。
6. 两种 Provider 适配器将 HTTP 429 的明确 `SetLimitExceeded` 识别为 `PROVIDER_USAGE_LIMIT_EXCEEDED / PERMANENT`，与普通速率限制区分。仅解析结构化错误码，不按错误文案猜测；公共错误信息不包含账号详情。
7. 验收驱动支持同一 Run 的既有重试，在失败后按正常取消/完成链路清理，避免污染下一案例。报告记录实际发布 prompt/schema 摘要，并保留脱敏、有界 Provider 诊断。CI 同时保留旧版七场景与新契约七场景。

配置语义和兼容范围见 [必要证据契约](../operations/published-evidence-contract.md)。

## 用量上限阻塞

真实 Provider 返回 HTTP 429、`SetLimitExceeded`，明确表示当前模型服务暂停。根据 [火山方舟官方错误说明](https://docs.volcengine.com/docs/ark/free-tokens-only-mode?lang=zh)，这是安心体验模式/模型用量上限，而非等待即可恢复的 RPM 限流。没有修改账户消费上限或切换模型掩盖结果。

恢复调用后，应在同一固定模型与预算下完整跑新契约原生/图端七场景，再进行独立重复批次；记录全部成功、拒绝、超时、调用数和费用。当前没有足够样本声明稳定成功率大幅提升。故障分类与持久收尾可用本地 HTTP 故障注入完成验收，不依赖继续消耗真实额度。
