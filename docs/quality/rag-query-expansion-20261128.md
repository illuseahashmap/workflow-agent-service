## 实现与兼容

- 模型在现有工具决策中按需生成 `auxiliaryQueries`；最多一条、1–2000 字。既有 `query` 仍是当前检索任务的主查询；可信原始用户输入继续保留在 Run/模型上下文。复杂任务不强行拿整段原始输入替换子查询。
- `RetrievalProfileVersion.queryExpansionPolicy` 为 `DISABLED` 或 `RRF_V1`。V84 为所有既有版本默认关闭；旧 Java 构造器、旧 JSON 和旧调用保持单查询。禁止原地修改已发布策略。
- 只更新工具目录的新 schema；旧 AgentVersion 的工具快照不改。模型可见 schema 描述辅助查询应保留实体和条件、不可臆造门槛或答案；没有新增一次强制模型调用或 Python 节点。
- 两路共用已授权租户、主体范围、发布 Profile、冻结索引与最终 K。先完成主查询，每路最多 K 条，合并前最多 2K；底层章节补取继续受原 seed/body 上限约束。用引用去重，RRF `1/(60+rank)` 求和后乘 `61/2` 归一化；同分优先主查询的稳定顺序，最终不超过 K。
- 每路先按冻结的原始 score policy 筛证据；融合分数使用独立 `RRF_NORMALIZED/query-rrf-k60-v1`，不拿旧阈值套新分数。保留两路的必要证据组，限额后缺组仍为 PARTIAL，不冒充充分证据。
- 主查询 PARTIAL/REJECTED/FAILED 不靠辅助查询掩盖；主查询 EMPTY 可由合法辅助证据补救。辅助重复、无结果、局部超时或已分类的临时 Embedding 故障可退回主路。权限异常、永久配置错误和总 deadline 不吞掉。
- 辅助路预算为 `min(2秒, 剩余时间/2)`；剩余不足 500ms 时跳过。HTTP 实际出站和 JDBC statement 接收运行时剩余预算，SQL 取消为 JDBC 秒级精度，返回时再检查精确 deadline。线程中断不应被当作正常成功。
- Trace 新增策略、结果/回退原因，以及每路 query 指纹、trace ID、状态、耗时和有序引用；不存查询明文或证据正文。最终 Trace 仍用于结果重新授权。完整工具参数沿用既有操作账本；同操作重放使用已持久结果，撤权后禁止交付。

没有实现新的 Token/金额硬配额。当前 Run 的调用数、截止时间和执行资格仍适用；内部检索次数和辅助耗时有上界，Embedding 用量完整计费仍属资源治理方案的后续工作。

## 启用方式

1. 按正常升级流程执行 V84，默认不改变旧版本的检索策略。
2. 使用现有 `POST /knowledge/retrieval-profiles` 创建新草稿，在原字段之外设置 `"queryExpansionPolicy":"RRF_V1"`；发布该版本。
3. 在新 AgentVersion 中绑定该 Profile 并发布，使工具元数据冻结为包含辅助参数的新 schema。旧 AgentVersion 不原地变更。
4. 完成真实答案/引用与成本验收后再扩大启用范围。回退使用原关闭策略的版本，不修改已发布版本。

本轮提供后端配置契约，不包含前端 Profile 表单改造。

## 辅助查询新增条件修复（2026-11-28 12:49，Asia/Shanghai）

根因不是 1500 的金额解析，而是原契约只靠描述要求模型忠实改写，Java 未区分主题扩展与事实条件改写。现在主查询保留原始事实，辅助查询限定为主题/制度类别词。没有金额阈值、审批人、采购场景或 caseId 专用判断。

- `AuxiliaryQueryPolicy` 的 `topic-only-v1` 进行 NFKC 归一化、控制字符/空白归一化，再保守识别数字（含全角、汉字、常见英文数词）、比较/范围、否定与适用条件词。
- 辅助查询只要带这些条件，即使条件曾出现在主查询，也不执行它；不删词拼成另一条查询，不推断“真正想问的范围”。主查询结果保持不变，Trace 记 `AUXILIARY_REJECTED_CONDITIONS_TOPIC_V1`。主查询为空或缺证时也不会被回退伪装成成功。
- 这是保守的词法边界，不是完备的自然语言语义证明。名称中带数字、部分正常主题词也可能被拒绝；代价是退回主查询，而非错误扩展。无法保证识别所有隐含条件、所有语言或实体幻觉，后续仍要做更多开发评测。
- 工具 schema 明确辅助查询只放主题词，主查询不附加指令、解释或假设条件。V85 更新工具目录供新发布版本使用，不更改旧 AgentVersion 快照；既有 `query`/可选 `auxiliaryQueries` 数据结构及旧 Profile 默认单查询保持兼容。即便旧提示词生成不合规辅助词，执行侧检查仍会拦截。
- 同一操作的历史回执仍按既有账本重放、重新授权，不通过本次代码更新重新执行旧请求。
