# Graph v2 确定性重复与短周期检测

日期：2026-11-20。接续 V70 稳定意图、V71 Run 次数预算与持久停止。本轮增加 V72，未迁移业务库、未切换发布版本。

## 实现

- Java 在新的 v2 工具调用获得外呼预留前判断可观测重复。判定、结构化证据和 `LOOP_DETECTED` 停止记录在同一个 Run 行锁事务中提交；提交后才向 Python 返回 `RUN_STOPPED`。Python 已有 STOPPED 检查点、Java 无模型收尾及 Flowable 失败策略继续复用。
- 动作指纹包含冻结 binding、工具代码、可信参数。JSON 对象键序与等值数字写法归一化，保留精确金额、数组顺序、主体、分页游标和业务字段。结果指纹来自成功工具账本与已提交不可变回执，并验证原始输出摘要。
- 不从客户端传入的计数、模型自述进展、随机 operationId 或图检查点恢复检测历史。每次新判定从 Run 的模型决策和可信工具回执重建；旧意图只读取自己前面的因果历史。缓存恢复不产生新判定、不累计重复事件，换 generation/进程不清空历史。
- 策略 v1 保留最近 8 个已完成的取证决策。对于拟再次执行的动作，其最近两次同动作结果相同，第三次提议停止；完整 `ABAB` 或 `ABCABC` 动作/结果序列重复后再次提议周期首项，在外呼前停止。结构化 pattern 分别为 `REPEATED_ACTION_RESULT`、`SHORT_CYCLE_2`、`SHORT_CYCLE_3`。
- 多工具模型决策作为一个因果组：对动作集合及“动作→结果”配对集合排序计算指纹，保留重复项数量。不会把同批次的兄弟任务完成顺序串成循环；相同完整批次重复也能检测，换批次排列顺序不能绕过。窗口单位为模型发布的取证决策组，不是 HTTP 返回顺序。
- V72 冻结每 Run 的策略版本及可忽略字段声明。默认不忽略任何参数/结果字段。可信宿主可在新增 reserve 重载中显式声明特定工具根对象中的 `traceId`、`trace_id`、`requestId`、`request_id` 为非业务元数据；工具结果也需单独声明。不凭字段名自行删除，不支持模型修改声明，不能声明忽略金额、订单或任意业务字段。
- 判定账本持有请求摘要、动作摘要、来源模型回执、参与比较的模型/工具回执及观察指纹。策略与判定表强制租户 RLS、禁止更新/删除。同 operationId 改请求拒绝，已停止 Run 的回执恢复、新调用与成功提交仍被拦截。

## 兼容与边界

v1 不经过新检测，旧 wire 和图节点保持原行为。V72 为已有 v2 Run 添加默认策略，历史从原有可信回执读取，不能按零开始。V71 的既有停止不因新迁移解除。已有 v2 原始回执继续复用，未替换 checkpoint。

这是**可观测动作/结果重复检测**，不是业务事实新颖性证明。新增参数/游标、变化的结果会允许继续；不据此宣称新分页合法或业务有进展。尚未实现事实版本适配、连续 6 次业务无进展判断、轮询例外、一次纠偏、Plan、泛化语义评委和真正的并行图。普通等待和未完成/异常的技术重试不加入成功观察历史，继续由物理次数预算和未知结果治理约束；摘要/最终答案也不能清空工具历史。未知长周期与持续变化的噪声仍由 Run 次数预算和 deadline 兜底。

未声明的随机输出元数据可能导致漏检；不能为提高命中率擅自忽略业务字段。工具内部嵌套调用计量和严格 Token/费用上限仍沿用上一阶段的未完成边界。没有进行真实模型、P-17 全业务金标或生产容量验收，G0–G3 未因此整体关闭。
