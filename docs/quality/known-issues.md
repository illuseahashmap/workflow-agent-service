# 当前问题与后续整改

更新时间：2026-08-10

本文件只记录尚未关闭的问题。已经完成的整改统一记录在 [项目状态总览](../status.md) 的“已完成基线”中，不再混入当前待办。

## P0：生产基线

### 1. 完整基础设施集成测试尚未在本机闭环

- 状态：进行中
- 当前情况：CI 已执行 Maven 验证；当前评审环境没有 Maven 和 Docker，未能本机运行 Testcontainers。
- 影响：PostgreSQL、Redis、Flowable、Flyway、RLS 和 HTTP 安全链路仍需依赖 CI 证明。
- 下一步：稳定 CI 容器环境，并将迁移、租户隔离、锁、事务回滚、重复消息和认证链列为必跑用例。
- 验收：发布分支完整 `mvn verify` 通过，并归档 Surefire、JaCoCo、SpotBugs 报告。

### 2. 生产可观测性仍不完整

- 状态：待处理
- 当前情况：已有基础日志、健康检查和部分审计。
- 下一步：统一 Trace ID、结构化日志、Micrometer 指标、Prometheus 端点、告警和失败命令恢复入口。
- 验收：可以按租户、流程实例、AgentRun 和 Trace ID 定位失败链路。

### 3. 流程操作审计仍需完整覆盖

- 状态：待处理
- 当前情况：已有安全审计和部分业务记录。
- 下一步：覆盖发起、领取、审批、驳回、转办、终止、规则命中、管理员操作和 Agent 执行。
- 验收：每个关键状态变化都能关联操作者、租户、时间、原因、前后状态和 Trace ID。

## P1：架构与质量

### 4. PostgreSQL RLS 尚未覆盖所有 Flowable 内部表

- 状态：进行中
- 当前情况：平台业务表已通过 V16 启用强制 RLS，应用层仍保留显式租户过滤。
- 下一步：逐表评估 Flowable 运行表、历史表的租户归属，并补充跨租户负面集成测试。
- 验收：无可信上下文默认拒绝；平台管理员和系统 Worker 经过显式授权；跨租户读写全部失败。

### 5. OpenAPI 响应模型仍需细化

- 状态：进行中
- 当前情况：公开 REST 路由已全量覆盖，CI 已执行 lint、路由覆盖和 PR 兼容性检查；部分响应仍使用通用 `ApiResponse`。
- 下一步：补充 DTO 响应模型、统一错误码、分页模型和前端类型生成。
- 验收：核心接口的请求、成功响应、错误响应和权限要求均可由契约直接生成和验证。

### 6. 核心模块覆盖率低于长期目标

- 状态：进行中
- 当前情况：JaCoCo 已配置构建门禁，当前阈值是保守基线。
- 下一步：优先提升 auth、租户隔离、流程并发、失败恢复、Agent 状态机和 Provider 适配器测试。
- 验收：核心模块逐步达到 60% 以上，关键安全和领域策略达到更高覆盖率。

### 7. 部分查询服务和 JDBC 仓储仍偏大

- 状态：待处理
- 当前情况：运行时与参与人协调职责已经拆分，部分查询聚合和仓储仍包含较多 SQL/组装逻辑。
- 下一步：按查询、命令、映射和持久化读写职责继续拆分，不把业务规则复制到 JDBC 层。
- 验收：大型类职责单一，领域规则有领域测试，仓储只负责持久化和映射。

## 已完成历史归档

以下问题已关闭，不再作为当前待办：

- 运行时服务和参与人协调器职责过大。
- 派单规则核心不变量散落在应用服务和 JDBC 实现。
- OpenAPI 没有契约、lint、兼容性和接口覆盖门禁。
- JaCoCo 没有真正的覆盖率 `check`。
- 登录/注册/租户切换仍把完整 Token 返回 JSON。
- Cookie 认证下的认证引导、CSRF 和生产 Secure 配置边界不明确。
- 租户隔离只有应用层过滤，没有 PostgreSQL RLS 纵深防御。
- Agent 管理、Provider 管理、运行账本和真实模型 Provider 基础链路缺失。
