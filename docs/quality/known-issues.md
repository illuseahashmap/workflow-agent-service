- 下一步：优先提升 auth、租户隔离、流程并发、失败恢复、Agent 状态机和 Provider 适配器测试。

### 7. 部分查询服务和 JDBC 仓储仍偏大

- 状态：待处理
- 当前情况：运行时与参与人协调职责已经拆分，部分查询聚合和仓储仍包含较多 SQL/组装逻辑。
- 下一步：按查询、命令、映射和持久化读写职责继续拆分，不把业务规则复制到 JDBC 层。
- 验收：大型类职责单一，领域规则有领域测试，仓储只负责持久化和映射。

### 8. AgentRun 过期任务和失效租约缺少回收闭环

- 状态：待处理
- 当前情况：Worker 已支持 `SKIP LOCKED` 领取、租约写入和迟到 Attempt 防覆盖，但只领取未过期的 `QUEUED` 运行；超过 `deadline_at` 的排队运行和 Worker 崩溃后租约过期的 `RUNNING` 运行没有扫描、续约、接管或终态收敛路径。
- 影响：排队超时或 Worker 异常退出后，AgentRun 可能永久停留在 `QUEUED` 或 `RUNNING`，无法依靠持久化账本自动恢复。
- 下一步：增加独立租约续约与 Recovery/Reaper 用例，通过条件更新回收失效租约，并将过期排队任务确定性转为 `TIMED_OUT`；接管时从最后完整 Checkpoint 创建新 Attempt。
- 验收：Worker 被强制终止、租约过期、运行排队超过 Deadline 时均能自动重试、接管或进入超时终态；旧 Attempt 的迟到结果不能覆盖新 Attempt。

### 9. Agent 输出 Schema 和结果策略尚未完整执行

- 状态：待处理
- 当前情况：发布时已校验平台支持的 JSON Schema 子集，Worker 已执行输入和输出结构校验，能够拒绝缺字段、类型错误、非 JSON 和空文本；但业务结果策略、空语义、部分结果和 Guardrail 尚未执行，成功输出也尚未按 BPMN `outputMapping` 写回流程变量。
- 影响：结构合法但业务不可用、证据不足或违反业务约束的结果仍可能进入 `SUCCEEDED`；流程只能获得固定的 `agentOutput` 快照，不能依赖节点约定的结构化变量继续路由。
- 下一步：建立独立的结果判定层，统一产生 `SUCCESS`、`EMPTY`、`PARTIAL`、`REJECTED` 或 `FAILED`；在流程恢复事务中校验输出契约并执行显式 `outputMapping`，禁止模型输出直接污染内部流程变量。
- 验收：合法、缺字段、类型错误、非 JSON、空结果、部分结果和策略拒绝均有自动化测试及确定状态；只有通过必需步骤和结果策略的运行才能进入 `SUCCEEDED`，映射后的流程变量可被后续网关和任务稳定消费。

### 10. 租户自定义 Provider 地址缺少生产级出站安全控制

- 状态：待处理
- 当前情况：OpenAI Compatible Provider 只校验 HTTP/HTTPS 和 Host，服务端随后直接访问租户配置的地址。
- 影响：恶意或错误配置可能访问回环、链路本地、云元数据和平台内部网络，形成 SSRF 和横向探测风险。
- 下一步：通过统一出站网关或平台级 Provider 策略控制协议、域名、端口和网络区域；解析并校验最终 IP，防止 DNS Rebinding，并限制响应大小和连接/读取超时。私有化模型地址必须由平台管理员显式授权，不能由普通租户配置自动放行。
- 验收：回环、链路本地、元数据地址、未授权私网、异常端口和 DNS 重绑定测试全部被拒绝；授权的公网及私有化 Provider 可以正常调用且留下审计记录。

### 11. Agent Worker 与平台定时任务尚未隔离

- 状态：待处理
- 当前情况：Agent 轮询任务在 Spring 默认调度线程中串行执行阻塞式模型 HTTP 调用，同一应用中的派单兜底和 Nonce 清理也使用 `@Scheduled`。
- 影响：单次慢模型调用可能阻塞其他平台定时任务；当前每轮最多五条的批次配置仍是串行执行，无法形成受控吞吐和租户公平性。
- 下一步：为 Agent 调度、模型执行和平台维护任务配置独立有界执行器；调度线程只负责领取，执行层增加全局、租户和 Provider 并发配额、队列上限、拒绝策略和指标。
- 验收：慢 Provider 不影响派单兜底与安全清理任务；并发、队列、拒绝和积压指标可观测；压力测试下不会产生无界线程或连接。

### 12. Flowable 完成与失败恢复仍是临时适配器

- 状态：待处理
- 当前情况：`AgentFlowableCompletionCoordinator` 定时扫描 `agent_run` 终态；成功时写入固定变量并直接触发等待执行，失败、超时或取消时直接删除整个流程实例。BPMN 节点中的 `failurePolicy` 和 `outputMapping` 尚未参与恢复决策。
- 影响：Agent 局部失败会被放大为流程实例终止，无法进入 BPMN 错误边界、人工接管、补偿或待运维状态；固定输出变量也会使流程定义中的配置与实际行为不一致。
- 下一步：以版本化完成事件替代终态表扫描，先写 Inbox 去重，再在独立事务和流程实例锁中校验运行上下文；成功时执行输出映射，失败时按冻结的 `failurePolicy` 进入 BPMN 路由、人工处理或运维恢复，禁止默认删除整个流程实例。
- 验收：成功、失败、超时、取消、人工接管和重复完成事件均有集成测试；任一 Agent 失败都不会绕过节点策略直接销毁流程实例。

### 13. Agent 节点激活标识不能区分循环重入

- 状态：待处理
- 当前情况：Agent 运行提交时直接使用 Flowable `executionId` 作为 `activityActivationId`，幂等键也由流程实例、节点和 `executionId` 组成。
- 影响：循环、驳回重走或补偿后再次进入同一节点时，Flowable 可能继续使用相同执行对象，导致新运行被误判为重复，或者旧运行的迟到结果恢复新的节点激活。
- 下一步：每次进入 Agent 节点时生成并持久化独立 `activityActivationId`，同时记录流程实例、Execution、Activity、AgentVersion 和 Attempt；恢复前逐项校验当前等待状态与激活标识。
- 验收：同一流程和节点连续进入多次均生成不同激活标识；旧 Attempt、重复事件和迟到事件不能推进新的节点激活。

### 14. Agent BPMN 部署校验未覆盖运行语义

- 状态：待处理
- 当前情况：部署时仅解析 `workflow:agentTask` 的位置、版本 ID 格式和基础属性，没有验证 AgentVersion 是否存在、已发布且属于当前租户，也没有完整校验输入输出映射、失败策略、超时、预算和输出变量名。
- 影响：前端虽然只展示已发布版本，但绕过前端或导入外部 BPMN 后仍可部署无效配置，错误会延迟到流程运行期并产生无法恢复的等待实例。
- 下一步：增加部署期语义校验服务和 AgentVersion 查询端口，冻结可执行的绑定投影；校验版本状态与租户、节点类型、监听器/异步属性、映射结构、变量命名、失败策略、超时和预算上限。
- 验收：不存在、未发布、跨租户版本及非法映射或策略均在部署前被确定性拒绝；成功部署的 Agent 节点具备完整且不可变的运行契约。

### 15. Agent BPMN 节点类型和前端配置契约尚未收敛

- 状态：待决策
- 当前情况：实施计划描述异步、可触发的 Agent Service Task，当前前后端实现则使用带启动监听器的 `ReceiveTask`；前端能够选择已发布版本和编辑输入映射，但 `outputMapping`、`failurePolicy` 与 `timeoutSeconds` 仍使用隐藏默认值，用户无法完整配置。
- 影响：设计文档、BPMN 语义和运行实现存在分歧；Receive Task 表达的是等待外部信号，而不是执行平台 Agent 服务。隐藏配置又会造成 XML 中存在契约但设计器无法维护。
- 下一步：通过 Flowable 行为、事务边界、失败路由和模型兼容性验证正式确定节点表示；随后统一设计文档、Moddle、解析器、部署校验和属性面板，不保留两套并行语义。
- 验收：导入、编辑、保存、重新打开和部署后节点语义不丢失；设计器可维护全部 MVP 绑定字段，前后端对同一 BPMN 契约有双向契约测试。

## 已完成历史归档

以下问题已关闭，不再作为当前待办：

- 运行时服务和参与人协调器职责过大。
- 派单规则核心不变量散落在应用服务和 JDBC 实现。
- OpenAPI 没有契约、lint、兼容性和接口覆盖门禁。
- JaCoCo 没有真正的覆盖率 `check`。
- 登录/注册/租户切换仍把完整 Token 返回 JSON。
- Cookie 认证下的认证引导、CSRF 和生产 Secure 配置边界不明确。
- 租户隔离只有应用层过滤，没有 PostgreSQL RLS 纵深防御。
- Agent 管理、Provider 管理、运行账本和真实模型 Provider 基础链路缺失。
