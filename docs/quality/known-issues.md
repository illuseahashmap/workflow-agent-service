# 已知问题与整改计划

更新时间：2026-08-03

本文档记录当前代码评审中已确认、尚未处理的问题。优先级用于安排修复顺序；完成后应补充自动化测试，并在合并前更新对应状态。

状态说明：`待处理`、`处理中`、`已完成`。

## P1：发布前必须处理

### 1. 自动兜底执行可能重复获取同一流程实例锁

- 状态：待处理
- 位置：`AssignmentFallbackTaskListener`、`ProcessInstanceTransactionExecutor`、`RedisProcessInstanceLock`
- 问题：任务监听器在事务提交后的同步回调中执行自动通过或自动驳回；此时外层流程实例 Redis 锁尚未释放，内层操作会再次获取同一把锁并可能等待超时。
- 影响：原事务可能已经提交，但调用方收到失败；自动兜底无法稳定执行，还可能产生状态与接口结果不一致。
- 修复方向：将兜底操作改为事务提交后可靠异步执行，避免在锁持有范围内重入流程命令；同时保证消息幂等、失败可重试和重复消费安全。
- 验收标准：覆盖自动通过、自动驳回、重复消息、执行失败重试和并发触发测试，不再出现同一流程实例锁重入。

### 2. 成员管理权限存在角色自提权风险

- 状态：待处理
- 位置：`AccessManagementController`、`AccessManagementServiceImpl`
- 问题：拥有 `member:manage` 的用户可以修改成员角色，当前没有角色层级约束，也没有阻止用户给自己授予 `TENANT_ADMIN`。
- 影响：普通成员管理员可能获得租户最高管理权限。
- 修复方向：引入角色授予边界和操作者权限校验；禁止自我提权，只有具备租户管理员授权能力的主体才能授予或撤销高权限角色。
- 验收标准：覆盖自我提权、低权限授予高权限、管理员正常授权、撤销最后一个管理员等场景。

### 3. 禁用租户可能导致平台管理入口锁死

- 状态：待处理
- 位置：`TenantManagementServiceImpl`、`AuthTokenAuthenticationFilter`、`AuthServiceImpl`
- 问题：当前允许禁用正在使用的租户或最后一个启用租户；租户禁用后，现有 Token 会被拒绝，重新登录也无法选择该租户。
- 影响：管理员可能无法重新进入系统并恢复租户。
- 修复方向：禁止通过普通管理接口禁用最后一个有效租户，并提供权限受控、可审计的平台级恢复机制。
- 验收标准：无法禁用最后一个有效租户；租户禁用与恢复均有明确权限、审计记录和集成测试。

### 4. 参与人需求解析没有遵循排他网关条件

- 状态：待处理
- 位置：`FlowableParticipantAssignmentCoordinator#nextUserTasks`
- 问题：当前向后遍历会跟随所有出口，没有区分排他网关与并行网关，也没有依据流程变量判断实际可达分支。
- 影响：流程发起或任务完成前，可能要求用户为不会执行的互斥分支配置参与人。
- 修复方向：复用 Flowable 的条件表达式语义计算可达路径；无法安全确定路径时不得自行实现简化表达式解析器，应返回明确的待决需求或延迟到分支确定后解析。
- 验收标准：覆盖排他网关、默认流、并行网关、嵌套网关和条件变量缺失场景。

## P2：功能完善阶段处理

### 5. 页面入口权限与支撑接口权限不一致

- 状态：待处理
- 位置：流程定义目录接口、用户目录接口及对应权限配置
- 问题：部分页面只要求业务操作权限，但页面依赖的目录接口还要求另一项权限。内置管理员通常不会遇到问题，自定义最小权限角色会收到 `403`。
- 影响：无法按最小权限原则组合自定义角色，前后端权限契约不稳定。
- 修复方向：按业务用例重新划分目录查询权限，或提供用途明确的受限查询接口，并补充自定义角色集成测试。
- 验收标准：仅拥有流程发起或派单管理所需权限的角色，可以访问完成该用例所必需的数据，同时不能访问额外管理能力。

### 6. 转办目标缺少租户内有效性校验

- 状态：待处理
- 位置：任务转办应用服务及请求模型
- 问题：当前主要校验目标类型是否唯一，没有完整校验目标用户是否存在、是否启用以及是否属于当前租户。
- 影响：可能产生无人能够处理的任务，且错误只能在后续操作中暴露。
- 修复方向：转办前通过租户用户目录校验目标主体；错误信息应区分不存在、已禁用和不属于当前租户。
- 验收标准：非法目标无法写入 Flowable，合法转办及并发转办具有集成测试。

### 7. 启动请求中的流程定义标识可能不一致

- 状态：待处理
- 位置：流程启动应用服务及启动请求模型
- 问题：请求同时携带流程定义 Key 和流程定义 ID 时，当前没有完整校验二者是否指向同一个租户下的同一流程定义。
- 影响：调用方传入冲突参数时，实际启动对象可能与请求语义不一致。
- 修复方向：优先收敛为单一权威标识；必须同时保留时，应校验 Key、ID、版本和租户的一致性。
- 验收标准：冲突标识返回明确的参数错误，不启动流程实例。

### 8. 登录和注册接口缺少防暴力尝试机制

- 状态：待处理
- 位置：认证接口及安全配置
- 问题：当前没有接口级限流、连续失败延迟或临时锁定策略。
- 影响：公开部署后容易受到密码爆破和资源消耗攻击。
- 修复方向：按账号和来源地址组合限流，设置渐进式延迟或短期锁定，并记录安全审计事件；不得通过错误信息泄露账号是否存在。
- 验收标准：覆盖连续失败、限流恢复、正常登录和多实例部署场景。

## 验证与工程化缺口

### 9. 关键基础设施集成测试需要进入持续集成

- 状态：待处理
- 问题：现有单元测试可以通过，但 PostgreSQL、Redis 和 Flowable 的部分 Testcontainers 集成测试依赖本机 Docker 环境，当前评审环境未实际执行这些场景。
- 修复方向：在 CI 中提供稳定的容器运行环境，将租户隔离、流程锁、事务回滚、重复消息和数据库迁移列为必跑测试。
- 验收标准：CI 在干净环境中自动完成 Maven 校验和全部基础设施集成测试，并保存测试报告。

## 非当前范围

- 候选组任务：平台当前暂不支持候选组，因此“候选组任务不可操作”不作为当前缺陷处理。流程建模、接口校验和前端配置应明确阻止或提示该能力不可用，避免用户误以为已经支持。
- Agent 能力：`agent-engine` 当前仍为预留模块，具体能力需要单独完成产品范围、领域模型、安全边界和运行可靠性设计后再实施。
