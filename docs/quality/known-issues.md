## P1：架构与质量

### 4. PostgreSQL RLS 尚未覆盖所有 Flowable 内部表

- 状态：进行中
- 当前情况：平台业务表已通过 V16 启用强制 RLS，应用层仍保留显式租户过滤。
- 下一步：逐表评估 Flowable 运行表、历史表的租户归属，并补充跨租户负面集成测试。
- 验收：无可信上下文默认拒绝；平台管理员和系统 Worker 经过显式授权；跨租户读写全部失败。

### 5. OpenAPI 响应模型仍需细化

- 状态：进行中
- 当前情况：公开 REST 路由已全量覆盖，CI 已执行 lint、路由覆盖和 PR 兼容性检查；部分响应仍使用通用 `ApiResponse`。
- 下一步：补充 DTO 响应模型、统一错误码、分页模型和前端类型生成。
- 验收：核心接口的请求、成功响应、错误响应和权限要求均可由契约直接生成和验证。

### 6. 核心模块覆盖率低于长期目标

- 状态：进行中
- 当前情况：JaCoCo 已配置构建门禁，当前阈值是保守基线。
- 下一步：优先提升 auth、租户隔离、流程并发、失败恢复、Agent 状态机和 Provider 适配器测试；补齐 `AgentFlowableCompletionCoordinator` 的成功、重复、迟到、坏事件、输出映射、人工处理和事务回滚用例。
- 验收：核心模块逐步达到 60% 以上，关键安全和领域策略达到更高覆盖率；Agent 完成事件消费者必须有 PostgreSQL 与 Flowable 集成测试，不能只依赖解析器和部署校验单元测试。

### 7. 部分查询服务和 JDBC 仓储仍偏大

- 状态：待处理
- 当前情况：运行时与参与人协调职责已经拆分，部分查询聚合和仓储仍包含较多 SQL/组装逻辑。
- 下一步：按查询、命令、映射和持久化读写职责继续拆分，不把业务规则复制到 JDBC 层。
- 验收：大型类职责单一，领域规则有领域测试，仓储只负责持久化和映射。

### 8. AgentRun 过期任务和失效租约缺少回收闭环

- 状态：待处理
- 当前情况：Worker 已支持 `SKIP LOCKED` 领取、租约写入和迟到 Attempt 防覆盖，但只领取未过期的 `QUEUED` 运行；超过 `deadline_at` 的排队运行和 Worker 崩溃后租约过期的 `RUNNING` 运行没有扫描、续约、接管或终态收敛路径。
- 影响：排队超时或 Worker 异常退出后，AgentRun 可能永久停留在 `QUEUED` 或 `RUNNING`，无法依靠持久化账本自动恢复。
- 下一步：增加独立租约续约与 Recovery/Reaper 用例，通过条件更新回收失效租约，并将过期排队任务确定性转为 `TIMED_OUT`；接管时从最后完整 Checkpoint 创建新 Attempt。
- 验收：Worker 被强制终止、租约过期、运行排队超过 Deadline 时均能自动重试、接管或进入超时终态；旧 Attempt 的迟到结果不能覆盖新 Attempt。

### 9. Agent 输出 Schema 和结果策略尚未完整执行

- 状态：待处理
- 当前情况：发布时已校验平台支持的 JSON Schema 子集，Worker 已执行输入和输出结构校验；流程恢复事务也只按冻结的 BPMN `outputMapping` 写入显式业务变量。但业务结果策略、空语义、部分结果和 Guardrail 尚未执行。
- 影响：结构合法但业务不可用、证据不足或违反业务约束的结果仍可能进入 `SUCCEEDED`。
- 下一步：建立独立的结果判定层，统一产生 `SUCCESS`、`EMPTY`、`PARTIAL`、`REJECTED` 或 `FAILED`，禁止未经结果策略认可的输出推进流程。
- 验收：合法、缺字段、类型错误、非 JSON、空结果、部分结果和策略拒绝均有自动化测试及确定状态；只有通过必需步骤和结果策略的运行才能进入 `SUCCEEDED`，映射后的流程变量可被后续网关和任务稳定消费。

### 10. 租户自定义 Provider 地址缺少生产级出站安全控制

- 状态：待处理
- 当前情况：OpenAI Compatible Provider 只校验 HTTP/HTTPS 和 Host，服务端随后直接访问租户配置的地址。
- 影响：恶意或错误配置可能访问回环、链路本地、云元数据和平台内部网络，形成 SSRF 和横向探测风险。
- 下一步：通过统一出站网关或平台级 Provider 策略控制协议、域名、端口和网络区域；解析并校验最终 IP，防止 DNS Rebinding，并限制响应大小和连接/读取超时。私有化模型地址必须由平台管理员显式授权，不能由普通租户配置自动放行。
- 验收：回环、链路本地、元数据地址、未授权私网、异常端口和 DNS 重绑定测试全部被拒绝；授权的公网及私有化 Provider 可以正常调用且留下审计记录。

### 11. Agent Worker 与平台定时任务尚未隔离

- 状态：待处理
- 当前情况：Agent 完成事件已使用独立单线程调度器、数据库租约和有界执行器，坏事件不会阻塞派单兜底与安全清理；但模型运行轮询仍在单次调度方法中串行执行，尚无租户和 Provider 并发配额。
- 影响：慢 Provider 仍会限制 Agent 运行吞吐，同一租户可能占据全部模型执行槽位。
- 下一步：将 AgentRun 领取和模型执行彻底分离，增加全局、租户和 Provider 并发配额、队列上限、拒绝策略和指标。
- 验收：慢 Provider 和坏完成事件不影响派单兜底与安全清理任务；并发、队列、拒绝和积压指标可观测；压力测试下不会产生无界线程、连接或重复领取，同一租户不能长期占满全部执行槽位。

## 已完成历史归档

以下问题已关闭，不再作为当前待办：

- 运行时服务和参与人协调器职责过大。
- 派单规则核心不变量散落在应用服务和 JDBC 实现。
- OpenAPI 没有契约、lint、兼容性和接口覆盖门禁。
- JaCoCo 没有真正的覆盖率 `check`。
- 登录/注册/租户切换仍把完整 Token 返回 JSON。
- Cookie 认证下的认证引导、CSRF 和生产 Secure 配置边界不明确。
- 租户隔离只有应用层过滤，没有 PostgreSQL RLS 纵深防御。
- Agent 管理、Provider 管理、运行账本和真实模型 Provider 基础链路缺失。
- Agent 空输入映射会隐式泄露全部业务流程变量。
- Agent 完成事件没有领取租约、异常隔离、退避、死信和受控运维恢复。
- 流程设计器在没有人工任务能力时错误开放 `MANUAL_REVIEW`。
- Agent 映射字段依赖自由输入，版本选择存在 100 条上限和 N+1 请求。
