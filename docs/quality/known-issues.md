# 已知问题与整改计划

更新时间：2026-08-04

本文档记录代码评审中确认的问题及其整改结果。优先级用于安排修复顺序；完成后应补充自动化测试，并在合并前更新对应状态。

状态说明：`待处理`、`处理中`、`已完成`。

## 2026-08-04 复评新增/重开问题

### 10. 成员新增接口对已有成员存在角色保护绕过

- 优先级：P1
- 状态：已完成
- 位置：`AccessManagementServiceImpl#addMember`、`JdbcAuthMembershipRepository#add`
- 问题：成员新增接口会先调用 `membershipRepository.add`，而仓储层对已存在成员使用 `ON CONFLICT ... DO UPDATE SET enabled = 1` 重新启用成员；随后角色变更校验把旧角色视为 `Set.of()`。当请求目标是已有成员时，该路径没有读取真实旧角色，也没有进入 `lockTenantMemberships` 和最后管理员保护。
- 影响：拥有成员管理权限但不具备租户管理员授权边界的用户，可能通过“新增已有成员”的请求覆盖已有成员角色；极端情况下可以绕过最后一个 `TENANT_ADMIN` 保护，导致租户管理入口被削弱或锁死。
- 修复方向：将新增成员与恢复/更新已有成员语义拆开；新增前应判断成员关系是否已存在。若允许恢复成员，必须读取当前角色、锁定租户成员关系、复用与 `updateMemberRoles` 完全一致的高权限角色授予/撤销和最后管理员保护。
- 验收标准：覆盖新增新成员、重复新增已有成员、恢复已停用成员、普通成员管理员修改 `TENANT_ADMIN`、撤销最后一个 `TENANT_ADMIN` 等测试；重复新增不能绕过角色边界。
- 整改：新增成员前锁定租户成员关系并读取真实当前角色；重复新增按已有成员更新处理，恢复停用成员前复用高权限角色边界和最后管理员保护。
- 验证：`AccessManagementServiceImplTest#readdingExistingMemberUsesCurrentRolesForPermissionBoundary`、`#readdingDisabledExistingMemberRestoresItOnlyAfterRoleBoundaryChecks`。

### 11. 驳回到指定办理人缺少租户用户有效性校验

- 优先级：P1
- 状态：已完成
- 位置：`WorkflowRuntimeServiceImpl#rejectTask`、`WorkflowRuntimeServiceImpl#buildRejectVariables`
- 问题：驳回请求携带 `targetAssignees` 时，后端会直接标准化并写入 Flowable 技术变量；只有未显式指定目标办理人时才调用参与人协调器，转办路径也有独立的 `requireTransferableUsernames` 校验。驳回路径未校验目标用户是否存在、启用以及属于当前租户。
- 影响：API 调用方可以把驳回任务指派给不存在、已停用或非当前租户用户，产生无人可处理的任务，并破坏租户内任务可达性。
- 修复方向：驳回写入目标办理人前复用租户用户目录校验能力；对多实例、候选用户和单办理人分别校验目标集合。候选组仍按当前范围明确拒绝。
- 验收标准：非法目标无法写入 Flowable；不存在用户、非租户用户、停用用户分别返回明确业务错误；合法驳回、并发驳回和多实例驳回有测试覆盖。
- 整改：抽象通用的 `requireUsableUsernames` 目录校验，并在驳回写入技术变量前复用；转办路径同步统一到该校验。
- 验证：`WorkflowRuntimeServiceImplTest#rejectsUnavailableExplicitTargetAssigneeBeforeChangingFlowableState`。

### 12. 参与人预解析未覆盖普通节点后的条件顺序流

- 优先级：P2
- 状态：已完成
- 位置：`FlowableParticipantAssignmentCoordinator#selectedOutgoingFlows`
- 问题：当前只对排他网关和包容网关计算顺序流条件；普通活动、用户任务、服务任务后的条件顺序流会被视为全部可达。Flowable 运行时会按 BPMN 条件执行，但预解析逻辑可能提前要求用户为不可达分支配置参与人。
- 影响：复杂流程启动或任务提交前，前端可能展示多余的下一节点参与人要求，降低建模体验并造成错误配置。
- 修复方向：对所有带条件表达式的 `SequenceFlow` 复用 Flowable 表达式能力进行可达性判断；默认流、并行语义和无法安全判断的场景应有清晰策略，不能简单遍历全部出口。
- 验收标准：覆盖普通任务后的条件流、默认流、条件缺失变量、条件返回非布尔值、网关与非网关混合路径等测试。
- 整改：普通活动节点统一按 Flowable 条件表达式选择出口，支持默认流、无条件回退和多条件命中；并行网关保留全分支语义。
- 验证：`FlowableParticipantAssignmentCoordinatorTest` 新增普通活动条件流、默认流、非布尔条件测试。

### 13. 覆盖率只生成报告，缺少构建门禁

- 优先级：P2
- 状态：已完成
- 位置：根 `pom.xml` 的 `jacoco-maven-plugin`
- 问题：JaCoCo 当前只配置 `prepare-agent` 和 `report`，没有 `check` 规则。即使核心模块覆盖率明显下降，`mvn verify` 仍可能通过。
- 影响：授权、租户、流程运行和失败恢复等高风险领域缺少可执行质量下限，新功能容易在低覆盖率状态下合并。
- 修复方向：先对 `auth-engine`、`workflow-engine` 设置保守覆盖率门禁，再逐步提高行覆盖率和分支覆盖率；安全边界、租户隔离、任务状态迁移和可靠命令应优先纳入更高门槛。
- 验收标准：CI 中 `mvn verify` 会执行 JaCoCo `check`；核心模块低于约定阈值时构建失败；覆盖率报告作为 CI 产物归档。
- 整改：为 `auth-engine` 增加行覆盖率 0.25、分支覆盖率 0.20 门禁；为 `workflow-engine` 增加行覆盖率 0.25、分支覆盖率 0.15 门禁。
- 验证：补充注册成功/失败、登录成功/失败、租户切换和多租户展示单元测试；`auth-engine` 当前行覆盖率 28.8%、分支覆盖率 27.6%，完整 `mvn verify` 已通过 JaCoCo 检查。

## P1：发布前必须处理

### 1. 自动兜底执行可能重复获取同一流程实例锁

- 状态：已完成
- 整改：新增事务内持久化的兜底命令、唯一幂等键、跨实例安全抢占、超时回收和指数退避重试；监听器不再在提交回调内重入流程实例锁。
- 位置：`AssignmentFallbackTaskListener`、`ProcessInstanceTransactionExecutor`、`RedisProcessInstanceLock`
- 问题：任务监听器在事务提交后的同步回调中执行自动通过或自动驳回；此时外层流程实例 Redis 锁尚未释放，内层操作会再次获取同一把锁并可能等待超时。
- 影响：原事务可能已经提交，但调用方收到失败；自动兜底无法稳定执行，还可能产生状态与接口结果不一致。
- 修复方向：将兜底操作改为事务提交后可靠异步执行，避免在锁持有范围内重入流程命令；同时保证消息幂等、失败可重试和重复消费安全。
- 验收标准：覆盖自动通过、自动驳回、重复消息、执行失败重试和并发触发测试，不再出现同一流程实例锁重入。

### 2. 成员管理权限存在角色自提权风险

- 状态：已完成
- 整改：应用服务增加高权限角色授予边界；禁止自我授予 `TENANT_ADMIN`，普通成员管理员不能授予或撤销管理员角色，并保留最后一个有效租户管理员保护。
- 位置：`AccessManagementController`、`AccessManagementServiceImpl`
- 问题：拥有 `member:manage` 的用户可以修改成员角色，当前没有角色层级约束，也没有阻止用户给自己授予 `TENANT_ADMIN`。
- 影响：普通成员管理员可能获得租户最高管理权限。
- 修复方向：引入角色授予边界和操作者权限校验；禁止自我提权，只有具备租户管理员授权能力的主体才能授予或撤销高权限角色。
- 验收标准：覆盖自我提权、低权限授予高权限、管理员正常授权、撤销最后一个管理员等场景。

### 3. 禁用租户可能导致平台管理入口锁死

- 状态：已完成
- 整改：仅平台管理员可变更租户生命周期；禁止停用当前租户和最后一个有效租户，提供显式恢复接口，停用与恢复均写入平台安全审计。
- 位置：`TenantManagementServiceImpl`、`AuthTokenAuthenticationFilter`、`AuthServiceImpl`
- 问题：当前允许禁用正在使用的租户或最后一个启用租户；租户禁用后，现有 Token 会被拒绝，重新登录也无法选择该租户。
- 影响：管理员可能无法重新进入系统并恢复租户。
- 修复方向：禁止通过普通管理接口禁用最后一个有效租户，并提供权限受控、可审计的平台级恢复机制。
- 验收标准：无法禁用最后一个有效租户；租户禁用与恢复均有明确权限、审计记录和集成测试。

### 4. 参与人需求解析没有遵循排他网关条件

- 状态：已完成
- 整改：使用 Flowable 表达式引擎计算排他与包容网关条件，支持默认流、并行及嵌套网关；条件变量缺失或结果类型错误时返回明确参数错误。
- 位置：`FlowableParticipantAssignmentCoordinator#nextUserTasks`
- 问题：当前向后遍历会跟随所有出口，没有区分排他网关与并行网关，也没有依据流程变量判断实际可达分支。
- 影响：流程发起或任务完成前，可能要求用户为不会执行的互斥分支配置参与人。
- 修复方向：复用 Flowable 的条件表达式语义计算可达路径；无法安全确定路径时不得自行实现简化表达式解析器，应返回明确的待决需求或延迟到分支确定后解析。
- 验收标准：覆盖排他网关、默认流、并行网关、嵌套网关和条件变量缺失场景。

## P2：功能完善阶段处理

### 5. 页面入口权限与支撑接口权限不一致

- 状态：已完成
- 整改：流程目录和用户目录按实际业务用例开放支撑查询，流程操作和派单管理角色无需额外管理权限即可读取必需目录数据。
- 位置：流程定义目录接口、用户目录接口及对应权限配置
- 问题：部分页面只要求业务操作权限，但页面依赖的目录接口还要求另一项权限。内置管理员通常不会遇到问题，自定义最小权限角色会收到 `403`。
- 影响：无法按最小权限原则组合自定义角色，前后端权限契约不稳定。
- 修复方向：按业务用例重新划分目录查询权限，或提供用途明确的受限查询接口，并补充自定义角色集成测试。
- 验收标准：仅拥有流程发起或派单管理所需权限的角色，可以访问完成该用例所必需的数据，同时不能访问额外管理能力。

### 6. 转办目标缺少租户内有效性校验

- 状态：已完成
- 整改：转办写入 Flowable 前统一通过租户用户目录校验，分别报告用户不存在、不属于当前租户和用户或成员关系已停用；当前明确拒绝候选组转办。
- 位置：任务转办应用服务及请求模型
- 问题：当前主要校验目标类型是否唯一，没有完整校验目标用户是否存在、是否启用以及是否属于当前租户。
- 影响：可能产生无人能够处理的任务，且错误只能在后续操作中暴露。
- 修复方向：转办前通过租户用户目录校验目标主体；错误信息应区分不存在、已禁用和不属于当前租户。
- 验收标准：非法目标无法写入 Flowable，合法转办及并发转办具有集成测试。

### 7. 启动请求中的流程定义标识可能不一致

- 状态：已完成
- 整改：指定流程定义 ID 时同时校验租户和流程定义 Key，一致性冲突直接返回参数错误且不会启动实例。
- 位置：流程启动应用服务及启动请求模型
- 问题：请求同时携带流程定义 Key 和流程定义 ID 时，当前没有完整校验二者是否指向同一个租户下的同一流程定义。
- 影响：调用方传入冲突参数时，实际启动对象可能与请求语义不一致。
- 修复方向：优先收敛为单一权威标识；必须同时保留时，应校验 Key、ID、版本和租户的一致性。
- 验收标准：冲突标识返回明确的参数错误，不启动流程实例。

### 8. 登录和注册接口缺少防暴力尝试机制

- 状态：已完成
- 整改：新增数据库共享的账号桶与来源地址桶，连续失败后渐进式临时锁定并自动恢复；登录错误统一为通用凭据错误，失败事件写入安全审计。
- 位置：认证接口及安全配置
- 问题：当前没有接口级限流、连续失败延迟或临时锁定策略。
- 影响：公开部署后容易受到密码爆破和资源消耗攻击。
- 修复方向：按账号和来源地址组合限流，设置渐进式延迟或短期锁定，并记录安全审计事件；不得通过错误信息泄露账号是否存在。
- 验收标准：覆盖连续失败、限流恢复、正常登录和多实例部署场景。

## 验证与工程化缺口

### 9. 关键基础设施集成测试需要进入持续集成

- 状态：已完成
- 整改：新增 GitHub Actions 后端校验工作流，在 Linux Docker 环境执行完整 `mvn verify`，并始终归档 Surefire 测试报告。
- 问题：现有单元测试可以通过，但 PostgreSQL、Redis 和 Flowable 的部分 Testcontainers 集成测试依赖本机 Docker 环境，当前评审环境未实际执行这些场景。
- 修复方向：在 CI 中提供稳定的容器运行环境，将租户隔离、流程锁、事务回滚、重复消息和数据库迁移列为必跑测试。
- 验收标准：CI 在干净环境中自动完成 Maven 校验和全部基础设施集成测试，并保存测试报告。
- 本次修复：Spring Boot 集成测试中 Flowable 会先创建运行时表，测试数据源因此不是空 schema；已显式启用 Flyway baseline，从版本 0 执行平台迁移，避免 `Found non-empty schema(s) "public" but no schema history table`。

## 非当前范围

- 候选组任务：平台当前暂不支持候选组，因此“候选组任务不可操作”不作为当前缺陷处理。流程建模、接口校验和前端配置应明确阻止或提示该能力不可用，避免用户误以为已经支持。
- Agent 能力：`agent-engine` 当前仍为预留模块，具体能力需要单独完成产品范围、领域模型、安全边界和运行可靠性设计后再实施。
