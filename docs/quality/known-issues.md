### 7. 部分查询服务和 JDBC 仓储仍偏大

- 状态：待处理
- 当前情况：运行时与参与人协调职责已经拆分，部分查询聚合和仓储仍包含较多 SQL/组装逻辑。
- 下一步：按查询、命令、映射和持久化读写职责继续拆分，不把业务规则复制到 JDBC 层。
- 验收：大型类职责单一，领域规则有领域测试，仓储只负责持久化和映射。

### 8. AgentRun 过期任务和失效租约缺少回收闭环

- 状态：进行中
- 当前情况：已有独立 Recovery 调度和专用租约心跳调度器，使用 `SKIP LOCKED` 扫描过期 `QUEUED` 和租约失效的 `RUNNING`；重试采用有界指数退避和随机抖动，最终 `available_at` 在失败事务中持久化。排队超时会收敛为 `TIMED_OUT`，失效运行会关闭旧 Attempt 后重新排队，下一次领取创建新 Attempt，迟到结果受 Attempt 条件更新保护。基于 Checkpoint 的多步骤恢复和强杀压力验证仍未完成。
- 下一步：在平台 Agent 具备多步骤执行后，从最后完整 Checkpoint 恢复，并补充 Worker 强杀、心跳失败和恢复压力测试。
- 验收：Worker 被强制终止、租约过期、运行排队超过 Deadline 时均能自动重试、接管或进入超时终态；旧 Attempt 的迟到结果不能覆盖新 Attempt。

### 9. Agent 输出 Schema 和结果策略尚未完整执行

- 状态：待处理
- 当前情况：发布时已校验平台支持的 JSON Schema 子集，Worker 已执行输入和输出结构校验，并通过基础结果策略区分空结果、内容过滤、证据不足、业务拒绝和长度截断；成功结果快照会记录策略状态和原因，流程恢复事务也只按冻结的 BPMN `outputMapping` 写入显式业务变量。租户可配置的业务结果策略、证据约束和 Guardrail 尚未执行。
- 影响：结构合法但业务不可用、证据不足或违反业务约束的结果仍可能进入 `SUCCEEDED`。
- 下一步：建立独立的结果判定层，统一产生 `SUCCESS`、`EMPTY`、`PARTIAL`、`REJECTED` 或 `FAILED`，禁止未经结果策略认可的输出推进流程。
- 验收：合法、缺字段、类型错误、非 JSON、空结果、部分结果和策略拒绝均有自动化测试及确定状态；只有通过必需步骤和结果策略的运行才能进入 `SUCCEEDED`，映射后的流程变量可被后续网关和任务稳定消费。

### 10. 租户自定义 Provider 地址缺少生产级出站安全控制

- 状态：待处理
- 当前情况：OpenAI Compatible Provider 已默认强制 HTTPS，拒绝 URI 用户信息、查询参数、异常端口、常见 IPv4 回环/链路本地/RFC 1918 私网、组播和无法解析的目标，并限制响应体大小及连接/请求超时；开发配置可以显式放行本地 HTTP。当前基于 `InetAddress` 便捷判断的实现没有完整覆盖 IPv6 ULA `fc00::/7`、CGNAT `100.64.0.0/10` 等非公网地址，标准 JDK HttpClient 也不能保证“校验 DNS 后固定连接到同一 IP”，私有化地址授权仍是全局开关。
- 影响：恶意或错误配置可能访问回环、链路本地、云元数据和平台内部网络，形成 SSRF 和横向探测风险。
- 下一步：短期使用明确的 IPv4/IPv6 CIDR 分类拒绝所有非公网目标，并补充 IPv6 ULA、CGNAT、保留地址和云元数据地址测试；长期通过统一出站网关或平台级 Provider 策略控制协议、域名、端口和网络区域，解析并固定最终连接目标以防止 DNS Rebinding。私有化模型地址必须由平台管理员显式授权，不能由普通租户配置自动放行。
- 验收：IPv4/IPv6 回环、链路本地、ULA、CGNAT、保留地址、元数据地址、未授权私网、异常端口和 DNS 重绑定测试全部被拒绝；授权的公网及私有化 Provider 可以正常调用且留下审计记录。

### 11. Agent Worker 与平台定时任务尚未隔离

- 状态：待处理
- 当前情况：Agent 完成事件和模型运行都已使用独立调度器；模型执行进入固定大小、有界队列的专用执行池，队列满时拒绝本轮投递并由下次轮询重试。全局并发和队列上限已建立，但尚无跨实例一致的租户和 Provider 配额。
- 影响：慢 Provider 不再阻塞平台定时任务，但单一租户仍可能占据全部模型执行槽位。
- 下一步：在领取查询中引入可持久化的租户/Provider 调度元数据与配额，增加并发、队列、拒绝和积压指标；不要使用仅单实例有效的内存信号量冒充分布式配额。
- 验收：慢 Provider 和坏完成事件不影响派单兜底与安全清理任务；并发、队列、拒绝和积压指标可观测；压力测试下不会产生无界线程、连接或重复领取，同一租户不能长期占满全部执行槽位。

### 12. Agent 输入数组映射与运行时构造契约不一致

- 状态：已修复首版边界，数组索引/通配输入映射暂不开放
- 当前情况：部署校验现在拒绝输入侧的数字索引和 `*` 通配路径；标量、嵌套对象和整个数组映射仍由运行时支持。输出侧仍可使用索引和通配投影读取模型结果。
- 影响（历史缺口）：旧版本曾允许流程部署成功后生成错误数组结构；当前新部署和交互查询已在后端拒绝这类路径，仍需前端与旧流程迁移提示完成一致性收敛。
- 下一步：前端同步隐藏或禁用输入侧索引/通配选项；如果后续确需按索引构造输入数组，应先定义冲突、稀疏数组、越界和多值投影语义，再同步实现前端、部署校验和运行时构造器。
- 验收：前端不能配置运行时无法构造的输入路径；部署校验拒绝不支持的输入数组目标；标量、嵌套对象和整个数组具有共享契约测试，生成的输入必须通过对应 Input Schema 校验。

### 13. Agent 完成事件人工处置记录缺少查询闭环

- 状态：待处理
- 当前情况：人工忽略已经使用独立 `IGNORED` 状态并保存原因、方式、操作人和时间，但运维列表固定只查询 `DEAD_LETTER`。事件被忽略后会从唯一的完成事件运维接口消失，新增处置字段只能通过数据库读取，`RESOLVED_MANUALLY` 也尚无完整命令和查询语义。
- 影响：平台管理员无法通过正式 API 回看已忽略或人工修复的事件，也无法在运维界面区分待处理、已重放、已忽略和已人工解决，审计证据没有形成可操作闭环。
- 下一步：提供按状态、租户、AgentRun、流程实例和处置时间过滤的运维查询；明确 `IGNORED` 与 `RESOLVED_MANUALLY` 的命令前置条件和不可变处置证据，正常投递、重放成功与人工处置分别展示。
- 验收：运维 API 可以查询待处理和已处置事件；忽略后仍可按事件 ID、目标租户、AgentRun 和流程实例定位；重复处置不能覆盖首次处置证据，跨租户操作继续要求平台管理员权限并完整审计。

## P2：平台能力

### 14. 本地 Outbox 完成事件仍是单消费者交付语义

- 状态：长期预留
- 当前情况：Flowable 恢复消费者处理完成后直接把源 Outbox 事件标记为 `DELIVERED`，当前只有一个消费者时能够工作，但该状态实际表达的是“workflow 恢复已消费”，而不是事件已经向所有订阅方发布。
- 影响：未来通知、计费、质量评测、审计导出等消费者订阅同一 Agent 完成事件时，一个全局 `DELIVERED` 无法表达每个消费者的独立进度，新增消费者可能迫使修改现有恢复协议。
- 下一步：保持事件信封和业务消费者 Inbox 不变；当出现第二类消费者时，将 Outbox 的职责收敛为发布到传输层，每个消费者使用独立 Inbox/Subscription Offset 记录处理进度，禁止共享一个业务消费完成标记。
- 验收：同一事件可由两个消费者独立重试和完成，任一消费者失败不回滚或伪装另一消费者的进度；替换 PostgreSQL 本地传输为 Kafka 等实现时不修改 AgentRun 和 Flowable 恢复业务契约。

### 17. Agent 交互契约尚未形成完整表单与外部渠道

- 剩余风险：复杂对象和数组仍使用通用 JSON 兼容输入；尚无版本化表单、字段权限、字典数据源、外部系统幂等提交和数据待补录任务。
- 下一步：按照[工作流与 Agent 交互数据契约](../architecture/workflow-agent-interaction-contract.md)逐步引入表单上下文和多渠道适配，不修改 AgentRun 或 Flowable 核心领域边界。
- 验收：租户可通过 UI 或受控系统接口提供任意版本化业务输入，运行实例可还原所用契约版本，复杂数据无需编写 JSON。

## 已完成历史归档

以下问题已关闭，不再作为当前待办：

- 运行时服务和参与人协调器职责过大。
- 派单规则核心不变量散落在应用服务和 JDBC 实现。
- OpenAPI 没有契约、lint、兼容性和接口覆盖门禁。
- JaCoCo 没有真正的覆盖率 `check`。
- 登录/注册/租户切换仍把完整 Token 返回 JSON。
- Cookie 认证下的认证引导、CSRF 和生产 Secure 配置边界不明确。
- 租户隔离只有应用层过滤，没有 PostgreSQL RLS 纵深防御。
- Agent 管理、Provider 管理、运行账本和真实模型 Provider 基础链路缺失。
- Agent 空输入映射会隐式泄露全部业务流程变量。
- Agent 完成事件没有领取租约、异常隔离、退避、死信和受控运维恢复。
- 流程设计器在没有人工任务能力时错误开放 `MANUAL_REVIEW`。
- Agent 映射字段依赖自由输入，版本选择存在 100 条上限和 N+1 请求。
- Agent 完成恢复业务规则位于 `workflow-boot`，偏离组合根边界；现已下沉到 `workflow-engine` 应用用例与稳定端口，并由 ArchUnit 固化依赖方向。
- 死信人工忽略与正常投递共用 `DELIVERED`，且缺少原因和业务审计；现已使用独立 `IGNORED` 状态、必填原因和目标业务上下文审计。
- Agent 输出映射未统一数组语义；现已明确支持读取整个数组、固定索引和 `*` 投影。输入数组目标的构造语义仍作为 P1 单独处理。
