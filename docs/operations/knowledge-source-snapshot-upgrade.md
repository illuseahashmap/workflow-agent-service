# 知识源完整索引快照与 Profile 版本升级

本次新增 V58；不修改已有迁移的 checksum。部署时先按摄取升级手册停止旧 Worker，执行迁移，再启动新版。

摄取会加载来源内各文档的最新有效版本，对同一集合切分并生成全部向量。构建/激活时校验集合；期间新增或更新文档使候选过时，则拒绝激活，让后续领取重建。当前采用完整来源重建以保证正确性；后续可按不可变文档版本及模型版本缓存 Embedding，但不得改变来源快照语义。

旧索引不原地补写，已有 Profile 的引用不变。需使用新增文档时，将完整候选激活后创建/发布新的 Profile 版本，并按现有发布机制绑定新 AgentVersion。历史 Profile 的只读回放仍指向原内容。

V58 初始化每个租户/Profile 的 last_version，后续创建在同一事务内锁定该计数器并递增，不再查询 MAX(version)+1 作为并发分配算法。创建失败事务回滚，计数器随之回滚。只通过应用命令创建版本，不能绕过身份计数器直接写版本表。

使用独立迁移/运行账号的部署，需由迁移账号为运行角色授予新增 knowledge_profile_identity 表的 SELECT/INSERT/UPDATE 权限，并保留强制 RLS；不能通过赋予运行角色超级用户权限来解决授权错误。

所有出站路径使用同一受治理传输。自定义 HTTPS 信任上下文仍保持主机名验证；测试私网端点必须显式注入测试地址策略，生产默认拒绝。传输不会使用任意系统代理代替连接校验；生产统一网关接入需另行审批配置和验证。
