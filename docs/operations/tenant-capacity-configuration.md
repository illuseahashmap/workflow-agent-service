# 平台与租户资源配额

更新时间：2026-11-26。本文对应 V80 及配套管理接口、前端；代码验收不代表已部署到业务环境。

## 页面与权限

平台管理员在“租户管理”工具栏选择“平台配额”，配置平台总上限和默认租户上限；在租户行选择“资源配额”，为该租户逐项覆盖或继承默认值。普通租户管理员不能读写这些接口，前端也不展示入口。浏览器写操作必须通过 CSRF 校验。

| 字段 | 含义与边界 |
| --- | --- |
| 未完成任务 `outstanding` | 所有执行后端的 QUEUED、RUNNING、PAUSED 任务数；暂停和等待不会释放此额度，业务终态才释放。 |
| 同时运行任务 `active` | 图执行器正在处理的任务数；挂起等待让出执行槽位。原生 Worker 的并发仍由原有配置控制。 |
| 同时外部调用 `calls` | 图调用许可额度，包括仍未确认释放的隔离许可；共享模型账户、连接器自己的上限继续同时生效。 |

页面显示查询时的用量快照和已生效上限，不是实时监控，也不是每秒速率限制。

## 继承、生效与冲突

每项租户覆盖值可独立设为 null，表示继承平台默认。正整数范围为 1–1000000，默认值和新提交的覆盖值不能超过平台总上限。有效租户上限是平台总上限与覆盖值（缺省时采用默认值）的较小值。平台总上限仍约束所有租户的总和；租户额度不是预留的专属资源。

降低平台上限时，已有较高租户覆盖值保留，但有效值受平台上限截断；以后提高平台上限可能使这些覆盖值重新生效。调整默认值会影响继承该字段的租户。保存同步更新准入限额，不重置已有用量。

降低额度不会取消或强制终止已运行任务。未完成任务额度不足时，新的准入请求被拒绝，需要调用方处理；运行或外呼额度不足时，图调度等待后续领取或恢复机会，仍受 Run deadline 和停止规则约束。不能承诺所有被拒绝的新任务自动重试。

读响应带全局配置 revision；写请求必须提交读取到的版本。任意管理员改动配额后，旧版本写入返回 409，页面保留输入并提供刷新，不能静默覆盖。配置写入与容量领取使用同一策略锁，变更记录操作者、目标及前后值到资源审计账本。

## 接口与存储

- GET/PUT `/agent-runtime/capacity`：平台总上限、默认租户上限。
- GET/PUT `/agent-runtime/capacity/tenants/{tenantCode}`：指定租户覆盖值、有效值、用量。
- 契约见 [OpenAPI](../api/openapi.yaml)。租户必须存在，接口仅允许 PLATFORM_ADMIN。
- `agent_graph_capacity_policy` 保存平台策略和 revision，`agent_graph_tenant_capacity` 保存租户覆盖；新表强制 RLS。`agent_run_admission` 继续负责所有后端的准入计数。

容量管理接口不要求开启图 Worker；配置额度不会自动启用 LangGraph。共享账户配置仍使用原有资源管理接口，不在此表单编辑凭据或资源绑定。

## 升级与运维

先备份并应用 V80、部署配套后端，再发布依赖新接口的前端。V80 为历史准入表中不同于默认值、且在支持范围内的租户硬上限建立覆盖值。升级前检查历史 DBA 自定义值与图策略的差异；超出支持范围的旧值不能假定会自动转换。不要手工归零 used 或删除调用许可来消除容量等待。

所有参与调度的 Java 实例应升级到支持租户覆盖的版本；旧二进制不理解新表，不能把混合版本运行当作完整租户额度保证。回滚前评估已有覆盖和同步后的准入限额；不要直接删表或回退迁移。Python 图和旧检查点协议不因管理表单发生变化。
