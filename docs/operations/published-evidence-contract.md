# 已发布的必要证据契约

`x-workflow-evidence` 是输出 Schema 的显式扩展。只有新版本声明它才启用；旧版本没有该扩展时，原生与图端均保留既有路径。业务定义发布后不可改写，Run 仍绑定原版本、原截止时间和原调用预算。

## 发布与执行边界

契约指定输入主体字段、决策字段、引用字段、已审核条款的完整 locator，以及每个决策需要的工具回执条件。`requiredCitations` 必须全部属于绑定的已发布检索 profile。涉及的工具必须在该版本工具快照中，执行模式必须为 PLATFORM_AGENT，输入主体必须声明为字符串。

决策字段必须有闭合的 `enum`，每个值必须且只能归入 `decisions` 或 `abstainDecisions`。前者需要主体匹配的原始工具回执，后者显式表示不作肯定业务判断的结果；流程设计者必须把后者绑定到补资料或人工处理分支。拼错条件或漏写一个枚举会使发布失败，不会默认为无需证据。

每个 `decisions` 条目包含 `tool`、`argumentSubjectField`、`resultSubjectPointer`、`allOf`、`anyOf`。主体由本次输入决定，必须同时匹配工具参数和结果；条件使用有限 JSON Pointer 和标量等值比较，数值按数学值比较。`allOf` 全部成立，非空 `anyOf` 至少一项成立。缺失、串单、冲突或畸形回执不支持肯定决策，不能当成反向事实。

最终答案必须引用全部 `requiredCitations`，且所有输出引用都必须来自本次实际成功检索的匹配 evidence/citation 对。模型在输出中写一个 locator 并不证明取得了该条款。原始回执通过现有租户、主体、权限、摘要及恢复归属校验；摘要和模型自述均不能补足证据。

## 成本与恢复

新契约对原始回执构造有限字段投影，供模型查看还缺哪些已审核引用、取得了哪些主体和事实字段。投影是数据，不是新授权；最终校验仍读取原始回执。原生路径不再为这种结构化证据调用可选模型摘要，历史普通任务的摘要策略保持不变。冷恢复从受验证的回执重建投影，而非信任快照中的摘要。

最终 Schema 支持 `oneOf`（严格恰好一个分支），用于约束 action/decision 等相关字段的合法配对。它不代替证据校验。没有合法配对的输出不能被当作成功；旧版有界格式修复仍受既有权限、预算与事实门禁控制。

v2 图遇到可信 Provider 适配器报告的永久错误时，持久写入 `GRAPH_MODEL_REJECTED` 并返回 RUN_STOPPED，由既有完成轮询提交失败和人工交接 Outbox。收尾不再调用模型、不延长截止时间，也不据此释放未知外部调用许可。暂时性 Provider 故障保留原重试语义，v1 wire 保持原行为。

HTTP 429 不总是可重试：明确的结构化错误码 `SetLimitExceeded` 表示账户/模型用量被暂停，两种适配器均转成永久 `PROVIDER_USAGE_LIMIT_EXCEEDED`。普通 RPM/TPM 限流继续保留有界重试。恢复服务需要运维处理 Provider 侧上限；平台不会自动调整消费配置。

## 试点

P-17 通过 `-Dworkflow.p17.evidence=true` 显式发布新契约版本；原 e1 文档与七场景 oracle 不改。只读政策版本不允许声明采购已具备条件；联合版本将 ORDER_READY 绑定到该单五项 MET，ORDER_NOT_READY 绑定到明确 INSUFFICIENT。所有正常结束结果都要求已审核下单条款，缺资料与故障各走原有分支。它是隔离验收模板，不是获得批准的生产采购政策。

报告保存实际发布的 prompt 与输出 Schema 摘要，区分是否启用证据契约。永久故障不能通过新建 Run、改预期任务或延长业务预算掩盖。验收驱动允许同一 Run 的既有持久重试，并在失败案例后用正常停止/完成链路清理，避免前一案例污染后一案例。
