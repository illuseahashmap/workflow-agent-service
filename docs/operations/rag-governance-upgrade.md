# RAG 治理 V59 升级与恢复授权说明

日期：2026-11-04。适用：本次恢复授权、结构定位契约、多来源索引冻结和有类型评分加固。不是 MinerU 部署手册；真实解析和父块扩展尚未交付。

## 升级前

- 备份目标数据库，保留当前运行/Checkpoint/工具审计与 Profile 清单；检查原 Profile 引用的索引与租户一致。迁移不猜测缺失或错误的索引。
- 暂停旧版 Agent Worker、知识摄取与 Profile 创建/发布写入口，再升级应用和数据库。不能让旧执行器继续绕过恢复授权，或让旧配置写入器创建缺少冻结成员的 Profile。
- 只执行新增 V59，不修改 V35/V37/V55/V56/V58，不盲目 flyway repair。迁移应在权限完整的迁移账号下执行；运行账号不因新表获得跨租户访问权。

## 数据变化与兼容边界

V59 为已有 Profile 只回填**原先实际绑定**的单个索引及来源，不给额外 Scope 选择新的 ACTIVE 索引；新增 source→index 绑定表带组合外键、RLS、发布不可变约束。新 Profile 必须从 DRAFT 创建，发布前来源成员与 Scope 完整对应；发布与成员变更串行化。新向量/混合快照中的成员要求同一 Embedding recipe。

已有文档/索引/AgentVersion ID 和原 Profile 字段不原地改写。ScorePolicy 的升级回填声明当前已有关键词/余弦/RRF 尺度，历史 HYBRID+关键词索引沿既有 KEYWORD 语义；不会回写历史 Trace 或假称过去已有新校准元数据。后续已发布 Profile（包括停用后）不能改回 DRAFT 或改分数/成员/Scope。

API 仍接受旧的单索引字段作为锚点；省略 indexBindings 只允许恰好匹配一个来源，多个 knowledgeScopes 不能替代索引清单。新 API 返回完整 indexBindings 和 scorePolicy。Trace 多成员时单索引字段为空，以实际 indexBindings 清单为准。已发布旧 Profile 继续按历史索引读取，不随当前 ACTIVE 变化。

用例交换格式升级为 case v3、locator v1、dataset v2；尚无已锁定生产旧数据集，草稿应显式重生成并校验，不添加无版本的兼容解析。业务运行原有 EvidenceReference/Chunk ID 保留；新结构化 locator 不意味着现有索引已拥有 PDF 解析产物。

## 恢复与处置

- 工具缓存不是权限凭证。幂等复用、恢复和每次后续模型请求均校验当前授权；知识结果还需有成功 Trace、原引用集合、Profile 绑定、当前主体范围与当前文档可见性。
- `KNOWLEDGE_RESULT_ACCESS_REVOKED` 表示历史证据失效/撤权/来源不可验证，不是模型暂时故障，不应自动重试外部调用或跳过校验。只有经正常授权流程恢复权限后，才可再次尝试恢复；证据已删除或业务版本需变化时，走人工处置或新的受权运行。
- 含工具历史的旧版 Checkpoint、工具账本缺失或 Trace 不可验证时拒绝恢复，不能把内存预览或模型摘要当作完整来源；即使工具已被撤权而不再出现在可用工具列表，也不能放行未验证的历史上下文。仅路由阶段、尚无工具结果的 Checkpoint 不受工具账本要求影响。已有审计继续保留，不删除记录来“解锁重试”。
- 权限校验保护后续边界，无法撤回此前已经发送给外部模型的数据。紧急撤权时同时按现有运维流程暂停/取消相关 Run。
- 授权/恢复查询与模型请求共享执行预算；耗尽返回 `AGENT_DEADLINE_EXCEEDED`，不是恢复知识权限的理由，也不能绕过校验重试。PostgreSQL 查询在 execute 前按剩余毫秒设置驱动取消并在结束后恢复 Statement 原超时。连接池等待/连接建立/取消传输仍需部署侧超时上限；不要把驱动取消当作进程强制终止。
- 新定位交换格式严格拒绝缺失字段、null 和隐式类型转换，不依赖补零恢复旧数据。关键词/向量同分现在按来源/索引/Chunk 稳定排序，可能改变旧同分 TopK；历史 Trace 不回写，评测新建基线，不修改已有报告来匹配新排名。

## 验收与回退

升级后检查 Flyway validate、旧 Profile 绑定与旧索引一致、新快照跨来源查询、授权子集、文档停用、非超级用户 RLS、发布后不可变及 V58 升级回归。回归不调用付费模型；真实 MinerU/浏览器/强杀门禁仍单独执行，不能用 Mock 或当前本地测试替代。

失败时停用新的创建/发布/恢复入口并保留诊断，不覆盖历史索引或重写旧 Profile。数据库只前进迁移；不得为了恢复运行回退到绕过知识结果授权的旧 Worker。生产放行还需目标账号/RLS与部署环境验收。
