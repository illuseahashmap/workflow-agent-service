## 发布与回滚原则

每次发布记录提交 SHA、迁移版本、artifact 摘要、测试报告、环境、发布负责人和回滚触发条件。没有负责人和证据的阶段保持未验收。发布/运维负责人确认步骤 3–5，开发评审者确认步骤 1、2、6；角色由实际发布流程指派，不由测试自动充当批准。

触发权限越界、预算超发、重复推进或未知调用丢失时停止新 Run 准入并保留账本。回滚只改变后续新版本的路由；已开始的图 Run 保留对应 artifact，按原状态恢复或终止。不得把图检查点转换成原生 Checkpoint，或靠清空预算/租约强行重跑。

## 范围控制

完成上述退出条件前，不新增通用图画布、第二套 Java 图调度或写工具。必要的治理修复可以进入主线；新的运行模式必须说明对退出条件的影响。原生代码仅接受安全、正确性及兼容修复，新编排能力默认只在图端实现。

状态表中的“已实现”“已验收”“已发布”“已退役”分别记录，任一项不能推导下一项。阶段完成时更新唯一状态入口及对应证据链接，问题清单只保留未关闭的风险。
