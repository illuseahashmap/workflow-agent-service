## §1 身份与权限

### §1.1 认证不等于授权（S-01）

个人账号、验证码和 API 密钥不可共享。成功登录只证明身份认证，不证明对某租户、知识范围、业务记录或生产环境拥有读取/修改权。授权要同时核验主体、资源、动作、租户、用途、期限和当前人员状态；模型不能通过提示词扩大 scope 或使用服务凭证冒充个人。

### §1.2 临时和长期权限（S-02）

访问申请需说明目标系统、权限级别、使用期限和业务依据。沿用手册锚点：临时权限最长有效期 **30 天**，到期自动失效；长期权限每 **90 天**发起复核。批准请求和技术权限实际下发是不同事实。转岗或离职时根据可信 HR 生效事件及时回收；权限到期并不证明已清理缓存、派生数据或所有外部系统访问。

### §1.3 数据最小必要（S-03）

访问和导出客户数据应限于完成授权业务所必需的字段、对象和时间范围。导出前确认保存位置、保留期限和接收人。不同租户的数据、向量、Chunk、检索 Trace 与附件必须保持相同权限边界。经过脱敏的数据仍需判断重识别风险；“去掉姓名”不自动等于匿名化或公开可用。

## §2 凭据与事件

### §2.1 凭据保管（S-04）

生产密钥仅保存在批准的密钥管理系统，不能写入代码、日志、工单、聊天群或知识文档。系统可显示凭据配置状态和受控尾号，不能回显完整密钥。密钥轮换完成需核验旧凭据撤销、调用方切换和审计，不是只生成新密钥。演示语料只能使用不可用的占位符。

### §2.2 疑似事件（S-05）

发现异常登录、密钥泄露、误发客户数据或生产数据异常时，应立即停止可能扩大影响的操作，并在**30 分钟内**联系信息安全部。报告包含发现时间、涉及系统、已执行止损和初步影响范围；不得为了等待完整根因才报。事件是否涉及个人信息、客户通知或监管义务由有权安全/隐私人员判断，模型不能直接宣告法律义务已经履行。

## §3 协作与拒答

业务负责人批准访问需求，安全/数据所有者判断范围与风险，IT 执行技术授权，HR 提供人员状态。任何一方“同意”都不能替代其他门禁。缺身份、租户、授权范围、资源类别或有效期时拒绝给出可访问内容；对无权主体，连文档标题与摘要也不应泄漏。安全事件回答只提供公开于该主体的处置步骤，不输出密钥、客户记录或攻击复现细节。

## §4 对照与发布

表 1：常见安全状态区别；规则见 §1—§3。

| 状态 | 能证明 | 不能证明 |
| --- | --- | --- |
| 登录成功 | 通过认证 | 有目标租户的数据权限 |
| 权限申请获批 | 业务/安全批准存在 | 技术授权已生效 |
| 令牌已过期 | 当前令牌不可继续有效调用 | 泄露事件已经关闭 |
| 文件已脱敏 | 完成某种字段处理 | 已不可识别或可公开 |

本政策不包含密钥截图或真实权限矩阵图片；表格即可表达决策边界。后续若有权限传播图，必须用合成主体并保留同等的文字说明。正式发布须核对权限数据源、事件上报渠道、手册 30 分钟/30 天/90 天锚点及现实隐私要求，填写批准与生效信息。
