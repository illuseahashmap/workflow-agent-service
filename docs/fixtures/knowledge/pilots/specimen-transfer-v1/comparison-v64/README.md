# 跨制度适用性：双方取证，不代替业务作决定

2026-11-09，PostgreSQL 18.1。沿用冻结原件、原问题、相同授权范围与 Top5。对比对象为[正常采集统计信息的 V63](../scope-postings-v63/README.md)。本实验不调用模型，不宣称 Flowable 或真实模型已通过拒答验收。

- **S05 两侧均可见**：两个规模均取回 L25（库内移交按编号登记，不走寄送报价核签）和 L5（冷链按承运总价分档），并附 L3/L23 标题；不召回低/高档或包装审批行。关键词结果为 SUCCESS，只表明双方有证据，不等于允许套用。
- **H10 缺发起方制度**：MD、XLSX、DOCX 都只返回检修的适用口径及标题，没有具体审批行。虽然 H10 的检索金标完整，作为跨业务作答依据仍为 PARTIAL / abstained。knowledge_search 不把单侧证据作为成功答案交给模型。
- 比较双方在不同授权来源、只准查任一侧、停用一侧、K 截断、阈值过滤、混合召回有额外相似金额行都有回归。只有标题不算支持；同一个块不能同时证明两个角色。混合检索仅可重排已确认的范围证据，纯向量路径不能验证两侧时拒绝。S06 同义指代仍未解决。

每格为热缓存下 64 次 search、每题 8 次，nearest-rank；单题 P95 此处就是该格最大样本。H10 Top5 的 MD/XLSX/DOCX P95 分别是 8.431 / 0.571 / 0.709 ms，每格式只有 4 次。双侧查找需要额外成本；不能根据总体 P95 推断比较查询都加速，也不能把这些本地数据当作 SLO。

**实现边界。** 系统把显式比较拆为发起方及参照方。在同一可见性查询内，金额表用原有目录定位标题和范围口径；无金额表的 Markdown 章节用标题前缀索引预筛、完整标题确认，再按原生清单获取本节的适用段落，不穿越下一标题、表格或列表。按角色轮流分配原预算；最终阈值过滤后再次校验每侧必要引用。V64 为既有块建立标题表达式索引，不改原件、Chunk ID 或已发布 Profile。部署时须允许查询角色读取已授权的原生派生清单，评估建索引的写入锁窗口。未覆盖任意语法、同义标题、复杂 Office/PDF 的无表章节或制度优先级判定。
