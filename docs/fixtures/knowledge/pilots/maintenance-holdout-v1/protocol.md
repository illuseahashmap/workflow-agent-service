# 设备维护制度预注册对照方案

状态：独立于采购开发题的合成留出集，同一研发人设计、未经过第二人盲审，不是发布金标。评测前冻结 inputs.sha256 内六个输入，不准用九道采购题代替。首次结果公开后，本版本转为回归集。若调整实现，用下一批未见材料评估泛化。

每次只放入一种格式的维护制度和同一份独立差旅制度。两个检索器共用同一事务、租户、显式测试范围、冻结索引、原问题及 K。对照是 dec4df2 的旧关键词适配器（仅改测试类名与 Spring 注册），不是关闭索引列后拿新 SQL 冒充旧引擎。走真实原件摄取和候选索引构建；计时仅 search 调用，不含解析、授权服务、模型或流程。不向检索器传业务答案或金标。

- 质量矩阵：10 题 × 3 格式 × K=3/5/10 × 2 策略。主指标为 requiredEvidenceGroups 全部命中（组间 AND、组内 OR）。另记 Top1 是否命中错表/错档及 TopK 内错表、错行条数；错表是非目标业务表或差旅原件，错行是 wrongRows 显式列出的同表干扰行。全局标题、口径不因未标注被判错。H10 无适用的审批表，其所需的适用范围依据不算错表，其余表中具体审批行不能替代缺失制度。召回了干扰项不等于真的用错了它。
- 质量评分使用格式原生位置，不匹配 chunk ID 或文本相似度；预检全部 18 处位置与原文片段。若不支持摄取，单列失败，不能用其他格式顶替。expectedDisposition/expectedAnswer 区分业务要求和实际检索结果，不给未执行的模型打分。
- 本机热缓存微基准，每个组合预热一轮、测四轮，固定交替 A/B、B/A；记录原始耗时，P95 取 nearest rank，每个格式/策略/K 有 40 个样本。质量每题只计一次，重复不稳定单独报错。没有并发、线上网络或大语料负载；不将本地 P95 当作 SLO。
